# V0.8.2 石墩、微信界面与战线延长

本轮修正工业区石墩被打扁消失、手雷补给过多和暂停按钮压住微信胶囊的问题，并加长第一关两个 Boss 之间的战斗路线。沿用 V0.8.1 的统一人物、平台和土层资源，本轮没有重新生成图片。

## 实际变化

- 工业区原先画成混凝土的 `steel-01` 改为真正不可破坏的 `concrete-B`，保持完整外形、真实承重面和碰撞。全部石墩经过子弹、刀击与爆炸的持续受击检查。可以正常跳上、跳过，不再压扁或消失。
- 射断吊桥后，桥面根据实际覆盖范围落在石墩顶面，随桥承托人物。此前只按预设地面停住，会穿进永久石墩；现在也支持随支撑移动及支撑消失后继续下落。其他桥、升降台和无柱通道继续回归。
- 手雷箱由五处减为两处：小 Boss 后 x=6950、最终 Boss 前 x=13090，每箱 +2，初始携带仍为 3。起点、沿路和隐藏普通箱不再发手雷。火箭筒继续仅有两个 Boss 前的必得箱；当前关卡没有霰弹枪或沿路通用补弹。
- 暂停按钮、点击范围、关卡文字和进度条共同避开微信胶囊。窗口坐标只换算一次，胶囊不占用整条屏幕右侧的操作空间；接口暂不可用时预留位置，延迟有效或旋转后重新布局。窄横屏任务提示改到第二行，修正旧的直接隐藏规则。

最终竞技场、战前火箭筒、手雷、缺血恢复点和出口随新路线一起后移。新增长压力段末尾有条件恢复，仍要求缺两格生命、附近无同类补给且本轮未领取；普通箱不随机掉血包。

## 验收

- TypeScript 检查及 **252/252 逻辑测试**通过。包括真实材质伤害规则、桥面落在石墩与支撑失效、携带人物、双向路线、敌人出生净空、供给预算、胶囊坐标与高 DPR 转换。
- 最终构建的第一关普通键盘通关 **96.79 秒，剩 1 格生命**；两次火箭拾取 x=4849.89、13245.67，第一处拾取时小 Boss 仍为 42/42。V0.8.1 同类自动路线记录为 79.65 秒。这些是可控浏览器时钟下的自动流程时间，不是人类游玩时长或手机帧率。
- 第二关普通键盘通关 **91.14 秒，剩 3 格生命**。重开、入场跳过、结算衔接、竖屏暂停、模拟双指和三种水下武器回归通过。
- 844×390 视口通过石墩持续射击、单跳、平台下双向通行、吊桥射断/承重、石墩站立与边缘离开、左右各四帧持炮步态、移动开火与竖直发射。
- Chrome 触摸视口模拟微信原生胶囊 API，检查 844×390、667×375、DPR 3、接口延迟、旋转、两章实际点击暂停与恢复。窄横屏任务文字确认可见。截图中的胶囊是测试覆盖层，**不是真实微信截图**。
- 初次专项把长时间原地射石墩、跳桥与后续路线连续执行，人物被附近敌人击败；失败保留于 `开发进度/验证记录/v082-details-exposure-failure.json`。耐击/吊桥与后续接触/武器专项现分为两次普通开局，不修改生命或传送。最终两关完整通关仍分别使用一条连续正常输入路线。
- 浏览器应用错误与资源请求失败均为 0。两平台本地构建完成；微信主包 **4,188,943 字节**，总目录 **12,607,671 字节**。资源包哈希与源文件、报告时间及技能副本均已核对。

**微信开发者工具、iPhone 真机及硬件震动本轮未运行；未上传或发布。** 原生 API 模拟只能证明布局与输入逻辑，不能代替微信真机适配或性能验证。
