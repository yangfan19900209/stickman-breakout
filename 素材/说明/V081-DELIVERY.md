# V0.8.1 人物全套统一、吊桥与战前补给

本轮针对人物笔触混杂、小石墩遗漏、吊桥连接中断、地下根须纹理杂乱和强武器过量进行整理。

## 实际变化

- 陆地主角的步枪、火箭筒、刀，以及普通敌兵，使用同一母版派生的完整人物图。站立、跑动、蹲行、起跳/下落、举枪、刀击、投雷、受伤、死亡与欢呼均检查实际选帧，避免换状态后跳回另一套画风。第二关岸边走路也沿用同一陆地主角；已接受的潜水人物保持其设计，并检查换装衔接。
- 移动步态按真实位移推进，持炮走路/移动开火均使用四个完整姿势，左右镜像采用相同的脚底和炮口坐标。没有拆身体、叠枪或用固定开火帧冻结腿部。
- 石墩检查包括内部名为 `steel` 的掩体。钢制与混凝土配置范围统一到 148 × 64 世界单位，按原画比例显示；承重面仍取实体顶面，不把吊环当作落脚点。受损但仍有碰撞时保持完整形体，只增加裂纹；破坏后才显示残骸。删除容易误认成微小路障的重复警示牌装饰。
- 吊桥两侧斜索、中央承重绳、滑轮和顶部连接形成连续结构，绳索命中范围和绘制端点共用 `bridgeRig`。正常跳上台面、射断绳索和落下后都已检查；平台下方通路不增加柱子。
- 地下填充替换为均匀的小型嵌入石块、少量短土屑，移除巨大的重复根须和大片长裂纹。保留手绘地表与自然石块，草土/混凝土区域共享同一安静内部材质；不改变主路高度。
- 第一关只保留 `rocket-before-tank`（x=4880）和 `rocket-before-colossus`（x=10870）两处必得火箭筒。第一处位于战车 740 单位警戒范围之外、升降台前的主路上，避免被上层路线跨过；实际拾取时战车尚未接战。移除普通/隐藏箱里的额外火箭筒、小 Boss 死亡火箭奖励及沿路通用补弹。霰弹枪从当前关卡获取路径移除；旧资源和底层兼容定义未作无关清理。

## 验证结果

- TypeScript 检查通过；244/244 逻辑测试通过，新增整族姿态、仅两处火箭来源、同类石墩尺寸、炮筒坐标和吊桥连接回归。
- 浏览器第一关普通键盘通关：79.65 秒，剩余 3 格生命；确实取得两处火箭筒，全程没有霰弹枪。第一处拾取坐标为 x=4852.76，战车仍为 42/42 生命且尚未进入其警戒范围。
- 第二关普通键盘通关：92.58 秒，剩余 2 格生命；鱼叉、声波、鱼雷仍可获得。验证岸边走路、换装、入水、通关衔接、重开、跳过入场、暂停与横竖屏恢复。
- 844 × 390 视口验证固定台下双向通行、单次跳跃登台、吊桥射断、石墩站立和离开边缘、左右持炮各四个步态、移动射击及向上实际出弹。第二关模拟双指游动与开火通过。应用错误与资源加载失败均为 0。
- 专项自动操作曾在尚未落地时发出跳跃按键，未登上桥；记录留在 [初次时序失败](../../开发进度/验证记录/v081-details-initial-timing.json)。测试改为等实际落地再按跳跃，未修改游戏物理或传送角色。举炮测试还检查冷却结束后的射击计数与新弹体竖直速度，不把上一发残留火箭当作新发射。
- 中途把战前箱放在上层路线下方，正常路线会跨过它，该次实际跑图只取得第二处火箭。最终移至升降台前的主路，并让普通敌兵出生点避开箱体；模型与浏览器都确认开战前实际拾取，不能仅凭配置的 x 坐标宣称“战前补给”。
- Web 与微信本地构建已更新，核对两张新运行图在两个构建中的 SHA。微信主包 4,188,943 字节，总目录 12,603,655 字节，分包逐项记录于最终报告。大小参考 [Cocos 3.8 小游戏分包文档](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/subpackage.html)，未上传或发布。

浏览器可控时钟下的自动路线时间不是人类游玩时长或真机帧率。微信开发者工具、iPhone 真机和硬件震动本轮未运行。
