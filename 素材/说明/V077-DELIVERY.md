# V0.7.7 密集战斗性能与移动平滑

[文档目录](../../doc/README.md) · [汇总验收](../../开发进度/验证记录/v077-verification.json)

用户反馈：iPhone 15 Pro 的微信小游戏在第二关敌人多时卡顿，第一关走路略有顿挫。本版针对逻辑负载、绘制和显示时序处理，保留现有画风、敌人数量和动态环境。

## 改动

- 第二关静态地形初始化空间索引，敌人移动、弹体扫掠、视线、激光和补给支撑只查询相关区域。精确碰撞依旧使用原有 803 个地形块，包括甲板接触和邻接岩石的嵌入恢复。
- 初始嵌入恢复直接寻找最近有效边界，复用查询缓存。没有降低物理频率或放宽穿墙判定。
- 小游戏预载一张战斗图集代替 83 张独立战斗纹理；保留尺寸、帧 ID、透明度和每个 RGBA 像素。浏览器保留本来有效的动态图集路径，平台差异依据本机 Cocos 3.8.8 源码核验。
- HUD 生命/进度向量图按实际可见变化重建；布局及章节切换清缓存。
- 第一关人物与镜头在固定物理步长之间平滑显示，不回写物理坐标。转向减速时步行相位保持向前；暂停、命中停顿、重开和胜利镜头直接使用当前姿态。

## 性能证据

同一台电脑、同一模型夹具，预热后每组 6000 个物理 tick。人为压力夹具持续维持 72 颗移动弹体；这些数值是单次逻辑更新耗时，不是手机帧率。

| 场景 | 原中位数 | 新中位数 | 原 p95 | 新 p95 |
| --- | ---: | ---: | ---: | ---: |
| 8 敌人、72 弹体 | 0.6041 ms | 0.0223 ms | 1.2960 ms | 0.0775 ms |
| 24 敌人、72 弹体 | 1.3174 ms | 0.0301 ms | 2.0757 ms | 0.0552 ms |
| 正常输入整关模型 | 0.1553 ms | 0.0141 ms | 0.4014 ms | 0.0445 ms |

压力夹具的玩家、敌人最终状态逐项一致；整关模型均为 10096 tick、77.5833 秒战斗计时、剩余 3 生命。报告：[优化前](../../开发进度/验证记录/v077-simulation-before.json)、[优化后](../../开发进度/验证记录/v077-simulation-after.json)。

Chrome 中关闭动态图集、分别保留独立纹理或使用静态图集，模拟小游戏的图像缓存配置。相同普通键盘路线、844×390 视口、1148 个有绘制帧：绘制调用中位数 **39 → 35**，p95 **44 → 38**，纹理绑定中位数 **28 → 24**。这只是引擎配置模拟，未运行微信容器。报告：[未合图](../../开发进度/验证记录/v077-browser-mini-unpacked.json)、[已合图](../../开发进度/验证记录/v077-browser-mini-packed.json)。普通浏览器维持原有动态合批，报告见[浏览器默认路径](../../开发进度/验证记录/v077-browser-after.json)。
