# 杨帆游戏开发体系

作为游戏开发的统一入口，按当前引擎、游戏类型、目标平台和实际问题，发现并组合使用所有已安装且可访问的相关游戏开发技能。适用于 2D、3D、不同引擎与玩法；保留用户选择的产品方向、画风和已有实现。

用户已要求游戏开发默认使用本体系并随迭代自动维护，无需每次点名。若当前仓库有 `doc/skills/yangfan-game-development/`，以其为本项目维护源；否则使用当前加载的安装副本。技术标识为 `yangfan-game-development`，界面名称统一为“杨帆游戏开发体系”。

现有参考文件保留了《线条突围》的 Cocos 2D 动作游戏经验，属于专项方法与实例。迁移前确认适用条件，不将其引擎、画风、数值、关卡或发布平台设为其他项目的默认要求。

## 开始工作

1. 读取当前项目约定、实际引擎与版本、目标平台、运行命令、用户已认可的体验锚点与已有改动；定位相关系统与资源的实际入口。
2. 将需求改写成可观察行为。例如“箱子不悬空”应覆盖完整箱体、破碎残骸、碎片和掉落物，分别确认支撑面与生命周期。
3. 记录复现位置、朝向、装备、血量、视口和输入顺序；截图中的视觉问题需同时检查资源、坐标变换和碰撞边界。
4. 按[已安装技能协作](references/skill-orchestration.md)选择并读取相关专项技能，再读取下表中适用的参考文件。沿用已有状态所有者与调用链，完成实际修改和适当验证。

## 组合使用已安装技能

所有已安装的游戏开发技能都可作为候选，包括后续新增技能；不以本文件列举的名称作为白名单。先用当前会话技能目录中的名称、描述和实际位置筛选，只加载与任务有关的技能正文与参考文件。需要补查时按[发现与选择流程](references/skill-orchestration.md)查找安装目录或相应提供方。

按引擎、玩法、输入、UI、反馈、性能、镜头、音频、资源、测试或发布需求组合方法。新技能复查或多个方案重叠时，记录“需补足 / 已有覆盖 / 当前不适用”的依据；日常小修不扩展成全技能审计。已有稳定方案通过检查即可保留。用户认可某段体验后，在下一轮相关修改前建立可恢复基准，并把预期变化与应保持的体验分开验收，方法见[验证与交付](references/verification-and-delivery.md)。

## 跨任务约束

- **状态与画面一致。** 沿用当前项目的权威状态与所有者；例如动作游戏中的装备、生命、击杀、碰撞和攻击时序由游戏逻辑持有，画面、HUD 和输入适配器消费该状态，避免维护第二份装备或战果。
- **空间来自实际几何。** 支撑、墙体、掩体、枪口和爆炸落点使用同一套真实坐标；不要靠隐藏传送、关闭碰撞或固定地面高度掩盖问题。
- **画面时序也是行为。** 预警应先于伤害，近战命中应落在有效帧，镜头与输入要在暂停、重开和场景切换后正确恢复。
- **资源需要契约。** 按资源类型记录来源、运行时用途和验收属性；精灵需检查实际尺寸、透明度、帧编号、脚底锚点与挂点，模型、骨骼、材质或音频按对应技能检查。生成工具的承诺不能替代实际检查结果。
- **尊重美术资源方式。** 用户指定生成图片资源时，按钮底板、摇杆和动作图标必须走图片生成与资源接入流程，不用手写 Graphics、Canvas、SVG 或几何占位图替代最终美术。代码负责布局、文本、按压、冷却与交互；已有明确的矢量资源项目不因此被强制重做。生成资源仍须遵守游戏原有画风，“有质感”不能擅自解释为金属、写实或高密度纹理。当前项目约束见[实例索引](references/project-examples.md)。
- **遵循既有美术语言。** 除非用户要求变化，角色、场景、道具和特效保持比例、细节密度与色彩的一致性。线条或手绘游戏还需统一最终显示尺度下的线宽与留白；新关卡可以更有层次，但不能单独提高纹理精细度或换成另一种画风。地图迭代把人物与既有关卡放在可比较的视口下验收。对已采用手绘素材的游戏，减少杂乱细节不等于删除自然轮廓和材质质感，严禁靠空白几何块、稀疏多边形符号或线框平台降低既有场景完成度。
- **结论跟随证据。** 按目标平台分别记录编译、逻辑测试、编辑器或浏览器运行、目标平台运行与真机输入等证据；例如微信包构建不能代替手机触摸与硬件震动验证。

这些是实现约束，不要求重写现有架构。具体速度、尺寸、血包阈值、关卡长度、动画秒数和包体限额必须根据当前游戏重新确定。

## 可执行资源检查

使用 [inspect_sprite.py](scripts/inspect_sprite.py) 读取图片元数据、透明像素、SHA-256，检查图集帧范围，或证明重新编码前后解码像素一致。依赖 Python 3 与 Pillow；不修改图片。

```text
python <skill-dir>/scripts/inspect_sprite.py <image.png> --require-transparency
python <skill-dir>/scripts/inspect_sprite.py <atlas.png> --frames <manifest.json>
python <skill-dir>/scripts/inspect_sprite.py <runtime.png> --compare <original.png>
```

帧清单支持 `frames` 数组（每项有 `id`）或 `frames` 对象（键为 ID）；每帧使用 `atlas: [x, y, width, height]`，可带 `anchor: [x, y]`。坐标从图片左上角开始。锚点允许位于裁剪框外；检查器不要求所有素材使用这一清单格式，现有格式可先导出只读检查数据。

## 完成工作

交付实际改动、必要资源与简短证据：什么行为发生了变化、通过了哪些验证、哪些平台尚未运行。资源类任务提供可检查的图集/帧表与来源记录；演出类任务检查关键时刻截图和状态恢复。只完成当前授权范围内的发布动作，构建本身不代表已上传或上线。

每轮完成必要验证后，读取并执行[自动维护规则](references/skill-maintenance.md)：总结实际使用的技能及有效方法，提炼可复用经验，更新或修正本体系中失效、重复的指导，校验修改并同步安装副本。此维护已获用户授权，不再询问是否更新；没有实质新经验时不制造改动。
