# 节奏、操作与呈现

## 延长关卡要增加经历

先画当前节奏：起步学习 → 压力上升 → 小 Boss → 恢复 → 新的组合挑战 → 大 Boss 前准备 → 大 Boss。

用户觉得小 Boss 与大 Boss 太近时，在两者之间增加有区别的地形和遭遇：例如平台纵向路线、移动载具/桥、掩体组合、旧敌人的新位置关系。随后给一次可理解的恢复机会。不要只加水平距离、重复同一波敌人或堆高血量。

验证真实通关过程中的用时、空走时长、受伤位置和敌人重叠压力。若游戏允许绕过敌人，保留这种选择；是否设置清怪门、返回路线或封闭竞技场由当前产品决定。

插入新路段时一起核对地面总长度、区域边界、Boss 出生与激活区、出口、战前武器、手雷和恢复点；不能只后移 Boss，把准备物资留在旧位置。提高密度时同时比较单位路程人数和同屏重叠压力，沿用分段激活与已有池上限，避免把总人数增加等同于同一时间全部攻击。

## 主路、平台与视觉密度

主路先明确一条连贯的基准高度，再为战斗位置、奖励路线或机关安排少量高层。不要为了丰富画面随意堆叠小台阶、浅坑和碎高差；环境丰富度也可以来自远近层次、材质变化与完整的植被/岩石组。用户要求拉平路线时，应同时修改关卡实体与渲染，并重新贴齐敌人、道具、绳索和升降终点，避免画面平了但旧碰撞还在。

简洁粗线风格的平台用完整台面、清楚的端部和少量有意义的细节，不把含支架、缆线、铆钉的整套复杂图块密集复制来加长。柱子和栏杆不是必需装饰；选择悬空平台时可只保留有厚度的手绘台面，并与角色的线宽一致。简化后仍保留清楚的接触面、完整轮廓与手绘质感。平台和支撑是否阻挡按最新交互设计分别处理，不能从外观自动推导。按人物完整可见高度检查站立净空，固定可选台面优先在单次普通跳跃范围内，不迫使玩家为路过而执行精确二段跳。

统一风格时同时审查箱子、桶、补给和背景建筑，不能只更换地形。背景可降低对比度，但多个半透明建筑重叠会让墙内透出另一套轮廓；先减少重复地标层、拉开布局，再检查静止与卷屏画面。远景留白与前景完整轮廓共同保证辨识度。

爆炸的冲击力由短促亮核、快速扩张、峰值保持、压力环、命中音效与有界局部停顿共同建立，不靠一直加粒子。区分实际爆炸伤害与敌人死亡的纯视觉爆炸，后者也需要一次音效事件，但不能重复结算伤害。先按镜头范围筛选震动/停顿，限制连锁触发频率和上限；图集、精灵槽与弹体池沿用预载和复用路径。

给黑白画风增加战斗颜色时，结合 `game-feel` 和 `game-ui-ux`，先遵守用户确认的用色范围与既有强调色。用户只要求突出攻击和爆炸时，统一这些瞬时特效的色相，用亮度和透明度表达过程；不要自行按火焰、能量、预警增加不同颜色，也不要把角色、武器或整颗弹体外壳染色。预警仍可通过黑白线型、闪烁和位置表达，烟雾与碎片保留灰度。统一同类弹药时检查玩家、普通敌人和各级 Boss 的全部爆炸分支，优先共用已有完整彩色动画；水下可保留气泡云外形并共用强调色，不必强行变成陆地火焰。按实际帧逐步验证亮核、扩张、消散，避免只改弹体而留下旧黑白爆炸。精灵池临时染色必须在下次普通绘制时复原，不能仅因透明度未变就跳过颜色重置；同时检查背景、普通子弹和烟雾没有串色。

普通命中不应只靠降低人物透明度表达。结合 `game-feel` 保留实体轮廓，用短冲击帧、受击姿态/小幅后仰、定向碎屑与已有音效建立接触感；已锁定的发射源不能被视觉位移带偏，实体击退仍经真实碰撞。一次命中在同一入口生成一次反馈，避免伤害回调和弹体循环各叠一层。分别核验受击时可见性、效果到期、连续射击上限与镜头稳定；图片验收和逻辑状态检查同时成立。

声音桥接按已发生的事件消费，不能只允许 `playing` 状态而丢掉同一帧已切成死亡状态的最后一击。暂停与静音时不积压待重放音效；重开、换关重置各事件游标与节流时钟，播放资源加载与本局状态重置分开处理。异步加载在所有者销毁后返回时释放资源。事件调用测试不能代替耳机、扬声器和目标设备听感验收。

## 挡路物的可见性

有碰撞的沙包、路障、底座要在目标手机视口中提前可辨认。以角色高度和可用跳跃能力确定有意义的显示尺寸，按原画比例同步实际碰撞框，而不是单独放大外框。留出周围的低细节区域：草丛、岩石贴花和界面覆盖不能掩住挡路物的轮廓或落地边缘。装饰避让按物体完整宽度及余量计算，检查不同屏幕比例下走近、被挡住和跳过的过程。

按最终外观检查整类障碍，不只按用户使用的名字搜索：同样画成石墩的对象，内部可能分别叫混凝土、钢制掩体或路障。审查这些类型共用的美术映射、尺寸和实体顶面，也区分没有碰撞的小警示装饰；统一尺寸不能漏掉另一个内部类型。受伤后仍有完整碰撞时，保持主体高度并用裂纹表示受损，不能提前切成矮残骸图，让隐形实体高于画面。

还要确认这种材质是否应当可破坏。设计为永久障碍的石墩应在关卡数据和伤害规则中保持不可破坏，仅让存活受损帧不缩小并不能阻止最终压扁消失。分别用子弹、近战和爆炸检查持续受击后的主体、碰撞顶面与掉落，再验证玩家仍可正常跳过。

## 补给遵循需求与位置

先确定供给点的语义：Boss 前准备、长压力段后的恢复、可见但需要冒险获取的奖励。再决定是否按玩家当前状态生成。道具数量不要只由随机死亡次数决定。

Boss 后的必得血包与低血量辅助恢复分开：在真实击败位置生成一次，满血时仍留在原地，缺血后按容量拾取；奖励使用同一掉落物理，空中击破也会落到实际表面。池满时保留重试机会，暂停不推进、重开清空本局标记，不能依赖只触发一帧且可能丢失的绘制事件。

Boss 阶段补给由会话中的真实血量和存活状态判定，用本局唯一标记防止反复触发；跨过阈值的一次大伤害也应生效，击杀则不再发中场奖励。池满后可重试，只有成功生成才记账。大型追击敌人应向玩家所在一侧释放道具，并避开实体身体和回退边界，落地仍用真实表面。保证基础武器、耗尽特殊武器和持刀状态均可领取所需装备；补给提示安排在血条下方，不能被交战时隐藏普通连击提示的规则一并吞掉。降低血量或增加爆发补给后，旧试玩不应强制普通击杀必须看完固定招式；计时阈值取当前最大血量，完整招式另用专项验证。

按 `level-design` 将 Boss 与后续遭遇分开时，后续敌人可保留在待生成队列，击败条件满足后再进入模拟、渲染与命中列表；只停止 AI 仍会留下可见、可受击的静止敌人。路段清理判断要计入待生成敌人，避免提前标记整段已清空。先核对战前缓冲与战后第一组的真实感知距离，再用正常输入验证首次生成、存活数量、奖励与战后喘息，重开不能继承解锁状态。

一种可选策略：

```text
玩家进入恢复点范围
且确实缺少有意义的血量
且附近没有同类补给
且本轮此恢复点未成功提供过补给
→ 尝试生成血包；仅生成成功后标记该点已使用
```

分别调整缺血阈值、触发范围、附近去重距离和每轮次数。资源池已满导致生成失败时，不要提前消耗唯一机会。Boss 战前检查道具能否在触发战斗前被玩家看见和拿到。

限定强武器出现位置或移除一种武器时，汇总全部获取路径：显式箱子、隐藏箱、随机掉落、敌人/Boss 死亡奖励，以及可延长强武器使用的通用补弹。只删显式箱子不能保证供给数量。用明确的关卡点位表达必得补给，并以实际流程确认到达、拆箱与拾取；同步调整旧名称、提示和验收路线，避免把不可用的弹药当成必需奖励追逐。战前准备点要在 Boss 激活范围之外，并检查上下分路是否会把玩家带到补给上方却无法拾取；位于 Boss 的左边并不代表能在开战前拿到。

减少一种武器时，不要把所有旧奖励箱机械地改成另一种消耗品。按初始携带量、每箱数量、容量和预期战斗消耗计算整关供给；普通箱子可以没有奖励。延长路线后的恢复仍放在高压力段末尾，并保留缺血阈值和一次性限制。

图标应能在目标手机视口中辨认；按类型设置显示尺寸，保留比例、脚底锚点与轻量阴影。用低幅度提示吸引视线，同时明确物理落点。不要通过剧烈上下漂浮掩盖没有落地的错误。

## 封面与结算构图

封面优先回答“是什么游戏、从哪里开始”：一个主标题、一个主要行动、一个体现玩法的主视觉。装饰使用游戏已有的风格与角色，标题、按钮、统计文本通常用引擎原生布局，便于小屏适配和本地化。

游戏内精灵来自同一项目，也不代表放大后能直接组成统一封面。先在最终显示尺寸下比较轮廓线宽、清晰度、内部细节密度和角色体型：低分辨率小人被大幅放大、精细机甲被缩小，会出现明显拼贴感。若差异无法通过合理尺寸解决，以原素材为身份参考，统一重绘场景；让人物、敌人共用透视、地面和接触阴影，明确其世界中的体型关系。

实现时按宽屏和窄屏分别检查主角、标题、开始按钮和安全区域；不要把整张带文字的海报缩小后当作全部 UI。设置项只保留用户实际需要的功能。系统浏览器界面、全屏支持或震动能力有平台限制，不用按钮文案承诺做不到的效果。

宽屏铺满可优先裁剪为排版预留的安静天空，把地面保留在下方；缩放上限依据实际角色脚底、机甲顶部等重要轮廓确定，不能只套通用 cover 裁剪。更窄的比例优先保留完整构图。插画与原生控件分别适配，并实际检查手机上按钮的触摸面积；装饰动画不要持续缩放命中区域。

## 触控与坐标

移除动作时同步清理触发组合、状态与碰撞分支、动画选择、按钮、教程和旧验收断言；验证原组合现在的普通动作以及低净空等边界。历史素材可保留归档，但运行路径不能继续提示已移除功能。

横版陆地与自由二维运动不要机械复用同一个向量解释。先确认产品是否需要轻推慢走：强调跑跳战斗、没有精细慢走需求时，可在小径向死区外直接输出正常跑速，把角色原有加减速保留在运动层；需要精细控制时再保留力度或提前达到满速。方向分类、起动/回中阈值、满速行程和摇杆外观半径分别设计，不把较大的视觉底座当作必须拉满的距离。水下和飞行继续消费原有二维向量。按 `input-systems` 的动作分层分别验证，避免改坏共用原始摇杆数据。

慢走排查同时覆盖角度与拇指行程：水平/斜向、短推/长推、偏右落指、抬起重按、持续开火都用相同轨迹对比。用户确认短行程才是原因时，应修正速度映射，并撤销为防慢走而过度收窄的下蹲扇区。上下动作要容忍自然的横向偏移，使用进入/退出滞回防抖；明确的斜推仍可行走加瞄准。速度测试选无障碍短路段或往返轨迹，避免跑到箱子前把正常碰撞当输入故障。按 CSS/窗口逻辑像素记录拖动距离，再转换到引擎坐标，不能把不同 DPR 的截图像素直接当拇指行程。

半透明战斗按钮同时检查底图、按压色、禁用色和冷却叠层，不能仅降低底图透明度却让冷却扇形重新盖住场景。可用常态必须明显区别于禁用态，过淡的轮廓会被理解成不可点击；保留透景时也要让图标、文字和按下反馈清楚可见。复用已认可的按钮图片，文字、库存标记、触摸面积与透明度分开设计；在实际背景和多指操作中检查后方敌人可见性及各状态辨识度，不能只核对透明度数值。菜单配色与战斗按钮配色分开，避免全局透明度改动误伤菜单。

一个 pointer/touch ID 拥有一个输入角色。摇杆与攻击、跳跃、投雷能同时操作，某个手指离开不能释放其他手指的按键。

二段跳、方向＋动作等隐含操作同时给出可回看的简短说明和当前状态反馈。例如空中有次数时跳键显示二段跳，用尽后提示落地恢复；提示应依据真实状态/冷却，不能只写文案却维持错误按钮状态。首次操作说明可限时显示，暂停页保留入口；章节切换到游泳时改回推进语义。重画按钮统一描边、图标、填色与按下反馈，视觉尺寸变化不能缩小真实触摸目标或挤入系统胶囊区域。

图标也要表达当前动作：跃起的人形、贴地滑铲、横向加速各有独立视觉语义，不能让陆地跳跃与水下冲刺共用向上箭头、只换文字。资源式按钮在生成时留出文字区域；数量角标的背景和文字一同放在冷却层之上。实际小屏检查常态、按下、冷却、无道具和章节切换；单看素材大图不能证明风格与可读性合格。

- 明确命中优先级，例如 UI/暂停 → 独立动作按钮 → 射击区 → 空白区快捷射击。根据当前产品布局调整。
- 浮动摇杆的真实按下原点与为了避免越界而夹紧的视觉底座可以不同，不要把视觉位移反馈成额外输入。
- 短按即使在下一次固定模拟步前已经释放，也要保留按下沿；持续状态与一次性动作队列分开。
- 在 pointer cancel、失焦、隐藏、旋转、暂停和重开时清除输入归属、排队动作及按住状态。
- 列明 CSS 像素、设备像素、UI 坐标与世界坐标转换，安全边距只换算一次；控制区不随世界镜头缩放。
- 旋转到不支持的方向可暂停；旋转回来只恢复由旋转造成的暂停，不能解除用户主动暂停。

小游戏胶囊等系统控件是独立的 UI 禁放矩形，不等于刘海安全边距。通过平台接口读取其窗口坐标，结合窗口/画布比例和留边转换一次，再共同布局暂停按钮、点击框与进度信息；截图出现胶囊旁附加圆形按钮时，一起预留这一组系统控件的位置。不要把胶囊宽度变成整条屏幕右侧的触控禁区。接口未就绪时预留合理空间；低频检查的布局键同时包含胶囊和安全边距，不能只在屏幕尺寸或胶囊改变时刷新。分别验证高 DPR、窄横屏、左右刘海、延迟更新、真实按钮点击和方向恢复，模拟胶囊测试必须标为浏览器模拟。

Cocos 3.8 的 `sys.getSafeAreaRect(false)` 已返回设计分辨率坐标，不得当成窗口像素再次除以缩放比例；浏览器 CSS `env(safe-area-inset-*)` 和微信胶囊窗口矩形则各自转换一次。依据实际安装的引擎实现确认坐标契约，避免只凭 API 名称推断。HUD、控件与命中区共用规范化后的边距。仅注入 CSS 安全边距的浏览器测试不能覆盖原生引擎的重复换算错误，应同时模拟引擎返回的设计坐标矩形。

验证至少包含同时移动与射击、边缘短按、手指拖出控件、触摸取消、暂停后松手、横竖切换。桌面鼠标通过不等于多指触控通过。

攻击冷却提示读取实际动作的恢复状态，近战不能借用枪械冷却。若最后一发后自动换枪、拾取换枪或动作间隔不同，保留发起该次恢复的时长元数据，不能用当前装备的时长重算上一击。检查起始、半程、恢复完成、切换、暂停和重开；提示修正不应顺便改动射速、弹药或伤害。

## 章节测试入口

需要反复测试后续章节时，提供稳定的直达链接或本地启动文件，刷新后仍进入指定章节。入口只选择章节，复用实际资源预载、会话初始化与状态恢复流程，避免复制玩法或通过调试传送跳关。浏览器参数经过平台边界传入游戏，不要求小游戏访问 DOM；横屏布局尚未可用时保留待进入状态，转到横屏后再执行一次。分别检查直接打开、刷新、方向切换和普通入口。

准备正式版时，将开发直达入口与已开放章节分开。隐藏测试按钮还要撤销对应热区，未开放章节在统一加载入口前拒绝；首页、结算主按钮、键盘确认和旧直达链接不能各自保留不同的下一关规则。最后一个开放章节给出可用的返回首页/重玩流程，避免重复按钮或空白结算。可保留仅本地生效的已开放章节测试入口，但公开链接不能沿用测试跳关参数。验证正常连续通关、旧按钮位置点击、旧链接和刷新、横竖屏恢复，并确认没有请求未开放章节的资源；原有源码和素材可留作后续开发。

## 镜头是玩法的一部分

普通跟随先明确前视量是否需要随朝向变化。单向推进且经常回身射击的游戏，固定推进方向的构图能避免短暂转身造成大幅横移；需要双向探索时再采用有滞回的速度前视。Boss 竞技场取景应能独立容纳敌人、预警和回避空间，玩家后退或转身时，大 Boss 不应立刻被镜头裁走。

结合 `camera-systems` 与 `game-feel` 排查“镜头晃”时，分开检查跟随目标切换、平滑插值、渲染层震动与角色局部后坐力。只减震动强度无法修复朝向翻转导致的目标跳变。用户要求取消镜头震动时，移除实际世界变换中的震动偏移，仍保留命中粒子、动作和音效；逐一检查不同章节的渲染入口。用相同位置轨迹、不同朝向序列验证镜头一致，再在浏览器记录真实世界变换和连续转向；反馈计时器仍触发不等于画面仍在震动。

先明确 Boss 是否允许脱战，再让激活、血条与取景遵循同一产品规则。持续追击型战斗保存“已交战”直到击破或重开，不用血量下降或当前是否跨过入口替代；后退仍保持适合完整身体与预警的缩放、前视。检查拾取提示、连击和路段目标等原本由战区开关隐藏的 UI，一并按持续交战状态避让血条，避免文字重叠。仅修构图时不暗改伤害；用户要求持续追击时也不能只保留镜头而让 AI 停机。验证满血首次进出、受伤后退出、远距离追赶、暂停与重开。

组合 `game-ui-ux` 与 `camera-systems` 调整“地面太厚”时，先量实际地平线占屏，而非直接裁掉土层资源或修改真实碰撞高度。通过镜头垂直构图减少无效区域，并复查跳跃最高点、开局主角与左右拇指控件的遮挡；必要时只调整开局镜头前视位置，保持人物出生点、关卡几何和移动参数。截图应包含站立开局与实际交战，不能仅凭窗口尺寸断言布局正确。

Boss 放大或增加跃进时，使用完整原画相对脚底的最高像素和实际跳跃最高点，扣除 HUD、血条与地面操作区域后计算取景。跳跃前摇阶段就平滑拉开镜头，避免等身体出屏后突然追赶；预警图标和肩部炮口也要留空间。不要通过缩窄受击框或移动真实角色来修复画面。浏览器需检查实际世界变换后的身体顶部与界面边界，覆盖起跳、最高点和落地，而非只拍站立截图。

需要镜头震动且用户接受时，将其叠加在稳定的相机目标上，结束后回到目标；不要累积修改相机基准坐标。UI 保持稳定，强度和时长有上限。移动端视口变化后重新计算需要展示的世界范围。

## Boss 死亡到结算的完整流程

将演出放进独立时间线：死亡确认 → 连锁爆炸/受损 → 主冲击/坍塌 → 镜头转向幸存主角 → 欢呼 → 结算入场 → 开放操作。秒数按当前节奏调整，不复制示例常量。

时间事件按序消费，使用 `while (elapsed >= nextEvent.at)`，每个事件只执行一次，避免掉帧跳过事件。暂停冻结时间线；恢复不重放震动，重开完全重置。

进入演出时确认最终 Boss 已死且玩家仍存活。同步冻结战斗用时与战果，停止敌人 AI 和战斗输入，清理存活子弹、手雷、枪口闪光、后坐力、投掷与受伤残留。不要只清掉弹体，遗漏武器系统的闪光计时器。

环境仍需维持必要更新：主角可以自然落地、残骸继续下落、视觉爆炸继续播放。视觉爆炸不再结算战斗伤害。世界更新如果依赖敌人列表判断区域完成，应传入真实列表；传空列表会错误宣布整关清空。

先让玩家看清 Boss 的崩溃，再拉近角色。保留真实世界位置，通过镜头构图安排主角和结果卡片；仅为构图强行传送角色容易暴露碰撞和背景跳变。采用完整欢呼动作帧，保持脚底基准并收起枪械。

结果面板可用渐入、位移与数字增长表现到达；开放再战前有明确可交互状态。暂停、返回标题和重开必须恢复镜头、时间缩放、输入、透明度与所有临时演出状态。

硬件震动由平台适配层尽力请求，失败时仍保留视觉反馈。测试中记录调用次数可证明时间线触发正确；是否真的震动需要支持该能力的设备验证。

验收关键帧：最后一击、第一次爆炸、主坍塌、主角近景、欢呼循环、结算完成、重开第一帧。检查所有残留闪光、武器、预警、统计变化与错误输入。

## 环境动态与过场动作

静态背景里已经画有鱼和气泡，不等于环境有动态。增加独立的低对比鱼群、持续上浮的气泡、带根部锚点的水草，并让运动跟随可暂停的游戏时间。按世界坐标布置，限定可见数量，循环边界放在镜头外；不要每隔一小段就在玩家眼前跳回起点。检查人物静止时的连续画面、跨区域镜头移动、暂停和重开，并让前景威胁始终更清晰。

岸边或过场中的自主移动若绕过正常玩家控制器，仍要推进动作所依赖的步幅/动画状态。步行帧按真实位移推进，动作选择器也必须实际消费对应步幅并切换完整帧；为只选待机/射击的敌人补走路分支，不能只推进计数。停下、抵墙和暂停时停止步幅，不能只改变位置或只累加另一个未被动作读取的时钟。

开箱、取装备等接触式过场先确定手部可触及的停位，再安排“停下→开盖→取物→装备→离开”。箱体与角色共用模拟时间线，开盖后保留打开状态；装备完成前持续按住方向也不能把人推进箱体另一侧。暂停应冻结双方，重开应同时复位人物、箱盖与装备。验证连续靠近、一直按住方向、阶段中暂停和重开，而非只检查最终换装结果。

用户要求全自动开场时，靠近道具也属于过场，不保留必须推摇杆才能触发的前置步骤。用同一过场状态决定逻辑输入与触控可用性，保留暂停；自然结束和重试跳过共用同一落点/装备结果，在交还控制的模拟步清理持续输入与未消费动作。无输入全流程、途中按住方向/攻击/道具、暂停恢复和跳过分别验证，避免刚恢复控制就误走、开火或消耗道具。

海崖前的水面不是从崖边横坐标起画的矩形。水体填充应延伸到整个取景区及岩壁后方，由前景悬崖自然遮挡；上边缘采用世界坐标连续的波面，浪纹与暂停共用模拟时钟。检查海面与崖壁交界、镜头横移和跃水过程，避免水体左边线或顶角暴露成贴上去的色块。

环境密度也受取景影响。海床、水草和沉船已经存在但长期在屏幕下方时，优先检查跟随高度，再决定是否堆更多装饰。环境层不遮挡敌人、攻击预警或必要的通行空间。
