# 精灵资源生成与接入

## 先建立资源契约

区分原始输入、风格参考、生成原图、切片、运行图集与截图证据。保存原图；运行时需要重新编码、裁剪或量化时另存输出并记录操作。

每类资源先约定：

| 项目 | 要回答的问题 |
| --- | --- |
| 用途 | 背景、完整角色帧、可替换武器、弹体、地形还是特效？ |
| 姿态 | 朝向、动作阶段、帧数、循环/单次、落地/空中？ |
| 画风 | 参考对象、线宽、填色、透视、光影和轮廓可读性？ |
| 坐标 | 实际裁剪矩形、脚底基准、中心、枪口及其他挂点？ |
| 透明度 | 背景透明，主体哪些区域必须保留不透明填色？ |
| 运行时 | 世界尺寸、采样方式、帧 ID、动画片段、预载和包体预算？ |
| 追溯 | 工具、提示词、参考图、源文件 SHA-256、筛选与处理记录？ |

实际生成时使用当前环境提供的图像生成/编辑工具并遵循其规则。涉及修改画面内容时使用相应图像工具；Python/Pillow 等用于授权范围内的确定性检查、切图、打包和编码处理，不拿拼接肢体代替需要的新动作原画。

## 不把生成承诺当作结果

提示词写清帧数、布局、边距和透明背景，但收到图片后重新读取实际宽高、alpha、每格内容和相邻帧间隔。生成结果可能不遵守目标尺寸，也可能多出碎片、缺帧或相互重叠。

先用接触表检查完整轮廓：头盔、脚尖、枪管、手指是否被截断，是否包含文字/网格/烘焙阴影，主体白色是否被抠成透明。明确选用和弃用哪些帧；不要为了凑帧数强行接入截断的动作。

例如指定 1536×512 的四帧图可能实际返回 2172×724；应按实际图片重新确认裁剪位置。格子均分只提供初始候选，最终边界仍以像素内容为准。

长枪管、刀尖或伸展的水草可能越过名义格线。可在格线附近寻找真实透明间隔，先确定行边界，再按每行内容分别确定列边界；没有干净间隔时停下人工检查，不强行均分。裁剪阈值只用于寻找边界，保留选中区域原始 RGBA，并检查低透明度尾迹是否被遗漏。鱼群、气泡等一帧可包含多个不相连的部分，不能把连通区域数量当作帧数。

帧名还要符合实际动作：提示词要求俯冲但输出水平滑游时，应改名为滑游候选并补画俯冲，不把错误姿态继续标成已满足。保存源坐标与生成记录，区分动作语义检查、裁剪像素检查和运行时动画检查。

## 完整角色、动作与挂点

接入正式图片后，旧占位或回退绘制必须覆盖完整状态周期的退出条件。只在存活状态跳过旧绘制，会在销毁前几帧重新叠出矩形、叉号或旧轮廓。遇到短暂黑框先分别检查原图透明度、图集边界及残留 Graphics 分支；用销毁初帧和后续烟尘/碎片截图确认原因，不能仅检查稳定帧。删除视觉标记时同时检查主绘制与回退绘制，保持碰撞、伤害和结算逻辑独立。

道具破碎不等于爆炸已经开始。延迟引爆或连锁爆炸应从破碎起持续采样，跨过闪光、扩张、最大火团与烟雾消散，核对每个实际选中的资源帧；单张破碎截图不能证明爆炸无边框。用户未看清瞬时框形时，检查方框以外的冲击圆环、椭圆和闪光底片等额外叠层，不用资源透明度正常就排除绘制问题。跨平台问题尽量补充对应图集配置与图形 API 的运行证据，并明确这些仍不是手机真机验收。

模拟目标平台的图集路径时，先检查项目资源加载器的条件。若静态图集由图像缓存清理配置选择，仅关闭动态图集并不会走到该路径；必须在资源预载前设置对应条件，再从实际 SpriteFrame 核对纹理尺寸、裁剪区域和完整帧序列。保留浏览器默认路径作为另一类证据，不把配置模拟当作目标设备运行。

如果资源是“完整人物持武器动作”，直接选整帧播放；不能在旧持枪身体上再叠一把新枪，造成双枪、错手和轮廓冲突。只有明确设计成骨骼/部件系统的素材才按部件组装。

动作清单至少覆盖实际会进入的状态：待机、移动、起跳/空中、落地、攻击前摇/有效/恢复、受伤/死亡，以及需要的欢呼或切换。缺少某状态时明确回退帧及可接受边界；不要默默回到携带错误武器的旧帧。

统一人物线条时以“角色族 × 装备 × 状态”检查实际选帧结果，覆盖主角、普通敌兵、过场中的同一角色和结算动作。只换当前武器的跑步图，会在切枪、自动刀击、投雷或受伤时重新混入旧笔触。保留已接受的换装设计，并用同尺度、同视口对照其头径与轮廓；统一资源需沿用稳定动作 ID、完整姿态和当前帧挂点，检查所有可达状态实际指向新图集。

持武器移动还要覆盖“移动且持续开火”：若攻击或瞄准分支总是覆盖移动分支，即使补齐跑步/游泳帧也会在射击时滑行。检查“装备 × 移动/停步 × 平举/斜举/上举 × 开火/停火”组合，并让受伤/死亡优先级显式可见。完整持枪帧使用同一姿态选择器决定画面和该帧炮口，按朝向做相同镜像；分别采样停火移动和开火移动的连续帧，确认四肢变化与发射点一起更新。每帧的实际筒轴可能有小幅手绘差异，初始弹道与该帧实测筒轴对齐，不能回到统一的旧炮口或用发射后急拐补偿。

检查完整序列中的武器连续性，尤其是“下落”候选图可能实际为空手跌倒。向上瞄准时若旧流程擦除原枪再叠旋转枪，不能只核对枪口位置：同时查看腋下、胸口和双手是否被遮罩切断。优先补完整举枪/空中帧并移除相应遮罩和 grip 覆盖；验证起跳、下降、开火/停火、左右镜像，而不是只看站立帧。

统一坐标约定。例如原图坐标左上为原点、Y 向下，裁剪后精灵高 `h`，世界坐标 Y 向上：

```text
origin = 原图裁剪框左上 + 透明边缘裁剪偏移
anchor.x = (soleSource.x - origin.x) / width
anchor.y = 1 - (soleSource.y - origin.y) / height
socket.x = (socketSource.x - soleSource.x) * worldScale
socket.y = (soleSource.y - socketSource.y) * worldScale
```

左右翻转时镜像挂点与角色使用相同变换。锚点可能在裁剪框外，例如把脚底基准设在墨线下方；不要机械夹紧到 0–1。所有帧使用共同世界比例和基准，不能每帧按包围盒高度独立缩放。跨图集换装时先对齐头部直径、肩宽与描边的最终屏幕粗细，再检查脚底/躯干挂点；固定显示宽度会让不同姿态的身体忽大忽小。保留完整人物帧，并同时检查换装前、装备中、跃入和恢复待机的连续画面。

枪口和脚底都要在实际游戏中检查：站立、跑动、向上射击、左右翻转、跳跃、换枪。原图坐标正确仍可能在渲染缩放或镜像环节错位。

为躲避路线减小 Boss 时，先用实际台面、人物跳跃轨迹和跨越耗时确定目标身体尺寸，再按该世界大小重画整套动作。不要用缩小旧图代替用户要求的重绘；原画同比例变小也会同时改变描边。新图先和实际人物在同一镜头下比较线宽，必要时用图像工具单独修订描边与透明边缘；修订后重新测脚底和炮口，不能假定编辑完全保留像素坐标。身体碰撞、受击框、挂点、取景和追击边界一起核对，完整验证左右换边，不只比较起跳最高点。保持统一采样比例，避免逐帧按高度拉伸。替换已有图集时可保留资源身份，逐帧核验未修改角色的 RGBA，防止顺便重编码或重画其他敌人。

大型飞行敌人的可见边界不等于碰撞主体：旋翼、尾翼、脚架常伸出碰撞框。用完整画面轮廓、当前可见世界高度和顶部界面占用共同确定出招空间，在短横屏中检查上下退路。追击阶段应先移动到可见区域再预警；已经锁定的预警和开火不要因相机更新瞬移枪口。优先采用稳定的章节取景比例，避免为补救裁切反复缩放镜头；浏览器截帧同时检查原画轮廓和实际攻击状态。

步态帧数量足够不代表包含完整循环。按“接触、承重、经过、另一腿接触”检查两条腿是否真正交替；剔除重复半步、烘焙烟雾和不相干的射击姿势。移动开火保持位移驱动的步态相位，用同一完整持枪帧提供炮口；不能用固定开火帧冻结腿部。统一源图采样比例，实际连续截图同时检查头径、脚底、枪口起伏和左右移动。

开火帧名变化不证明有动作：合图可能让多个开火 ID 指向同一裁剪矩形，应检查运行时实际纹理与连续画面。使用整身后坐回弹时，共享其变换给角色、枪口火光和物理出弹点，不能只偏移角色让枪口脱离。短火光需覆盖允许的最大模拟追赶间隔，或以渲染消费的事件确保至少显示一次；不能用全场停顿延长可见性。带长尾迹的普通子弹同样需要按已飞距离从弹头逐步露出，裁剪缓存保持有界，避免首帧尾迹穿进身体。

枪口火光属于角色挂点效果：在短暂可见期内按当前姿态、朝向和位置重算，不能一直停在开枪瞬间的世界坐标；已经飞出的弹体仍独立运动。敌人多炮管需保留本次实际发射的管口编号，下一帧跟随同一管口。回弹量若按每秒固定速率递减，实际持续时间是初始量除以衰减率，不能把初始量直接当作秒数；同时核对松开攻击、移动转向、最后一发自动退回基础装备及主动换刀。验收可将原图枪口像素经实际精灵变换投到场景中，再与火光挂点比较，避免只比较两个调用同一函数的状态值。

从已有图集继续裁剪出膛弹体时，局部裁剪坐标需加到当前帧的图集矩形原点，复用其纹理并保持高度和弹头锚点；不能误按整张纹理起点裁剪。量化裁剪宽度以限制缓存数，弹体对象复用时清零累计飞行距离。章节退出后先让精灵释放引用，再销毁派生裁剪帧和清空缓存；重新进入必须绑定新一代纹理。默认浏览器图集路径与目标平台静态图集路径分别核查。

姿态参数从角色对象转成普通对象时，注意对象展开不包含原型 getter。若动画、装备等来自 getter，应显式读取这些值，否则画面用跳跃/下落帧，发射计算却可能退回待机。枪口和筒轴必须消费同一完整状态，而不是分别构造不一致的副本。

## 地形与平台的重复模块

先区分短平台的完整美术和长地形的重复材质。少量固定长度的短架子可以整张等比缩放，按实际梁体顶/底线同步生成碰撞；重复整座复杂支架会让画面密度随宽度失控。需要更长结构时只延展安静的梁体，两端支撑完整保留并限制装饰数量。固定架子的脚应接到实际地面；可拆开栏杆/梁、立柱和脚座，仅延长立柱，保留其他部分的原画比例。升降或吊挂平台沿用导轨/吊索，不挂着一套悬空桌脚。主路即使是一块平地，也可按区域切换表面材质；这些美术分界不应生成新的碰撞高差。

将可重复主体、端帽、拐角、支架、破口分开。重复纹理检查左右/上下边界的线宽、亮度和图案连续性。最后不足一格的部分裁剪显示，不把整块拉长到平台宽度。

不同长度的台面应保留等比例端帽与描边，沿安静的梁身延展，避免横向放大、纵向压缩造成横竖线粗细不同。装饰面板与斜撑按完整单元安排，剩余长度由无竖线、无图案的梁身吸收，不在末段裁掉半个面板或铆钉。表层过渡选安静区间；深层填充共享世界 X/Y 相位，不能为了从“安静上缘”开始而在每块实体或每次材质切换处重置 Y 偏移。材质变化不能改变主通路的物理高度。

局部梁身使用独立横纵比例时，所有消费方必须传递完整变换契约；静态地形正常并不代表吊桥、升降台也正常。优先传结构化 tile 对象，避免新增 `scaleY`、镜像或透明度参数后旧调用漏传，导致横向补缝片被纵向拉成高竖条。材质变体与重复相位由世界坐标或稳定对象 ID 决定，镜头偏移只在最终绘制时应用。回归实际精灵的最终宽高、卷屏前后的样式、吊挂/升降/落地状态，并查看用户截图对应位置。

吊挂台面应从完整结构推导连接点：台面两端的斜索汇入承重索，承重索接滑轮/顶部固定处；不要分别画几根任意长度的立线。可切断绳索的碰撞区与绘制共用端点数据，断绳后清理失去支撑的绳段，保留合理的顶部残段。分别检查完整悬挂、正常登台、射断与落下后的画面，绳索装饰不能意外阻挡通路。

按统一原画比例铺设，再对齐碰撞顶面。相邻实体埋入地面的内侧边缘不重复画墙线；装饰支架不会自动成为碰撞体。用跨段走动、双向通路和台阶出口验证拼接处真实可通行。

线稿地形可使用透明上沿覆盖共同填充底色，但需确认底色、接缝和被遮挡的侧边连续。美术模块变化不能偷偷改变玩家站立面。

深层填充要覆盖镜头能看到的全部范围，包括关卡起终点外的取景余量；装饰延伸不改变可行走边界。相邻高低台阶的填充共享世界纹理相位，末行裁短时保留对应的源图偏移，不能从纹理顶部重新取样。固定平台、升降台与放下后的桥采用同一支架/梁体规则，并分别核对可站顶面和可穿行底面，避免仅静态地图换了美术。

表层与内部材质应使用不同的重复契约：草冠、横梁、楼板、面板框和植被只出现于对应表面，不能裁成窄条再向深处反复铺设。地基采用没有表层语义的连续土石或混凝土纹理；镜像重复可消除硬接缝，但仍要在实际视口检查对称花纹与密度。高低台阶的外露侧壁按真实高度差生成完整轮廓，在相邻填充之后绘制，不能仅裁取原画可能透明的末几列像素充当收边，也不要用显眼的纯白竖条盖住材质。视觉验收应回到用户标出的桥端、转角和深层内部，几何覆盖测试通过不等于这些画面已经自然。

用户要求达到既有章节的完成度时，先对照角色与各关已接受画面的结构、墨线层级和材质密度；完成度不等于越画越密，也不等于越简越好。对手绘位图场景，删减的是噪点、过密排线和重复结构，保留草冠、根系、圆润岩面、材质转折与完整钢梁支架。不得将这些已完成的美术换成空白阶梯矩形、灰色多边形或只有线框的桥。需要统一时，以用户接受的章节为参考补画相同笔触的完整素材；连续几何可以负责底色、遮罩、碰撞与细小收边，不冒充最终材质。

跨关验收至少保留相同视口/缩放下的“人物＋第一关地面/平台”和“人物＋新关卡对应结构”。检查外轮廓粗细、内部线条疏密、身体相对大小、留白、远近对比和接触边缘，不能只比较脱离场景的源图。连续介质还要检查前后场景的色彩：例如海面到水下保持同一水色体系，避免切换背景图后蓝水无故变黄。关卡主题可不同，颜色变化必须具有明确环境含义。

地面是相邻矩形实体并集时，从并集获得连续的覆盖与收边范围，保留每个高低转角；这不是把矩形轮廓本身当作最终美术的理由。内部手绘材质保持世界相位，表层只出现一次；高出站立面的草丛用完整单元或完整独立植被，不能在台阶角点裁断叶片。固定平台与移动平台都使用同一手绘梁体，核对可站顶面和可穿行底面。

从透明地形原画提取碰撞时，先标定实体主体的上下区间，将冠部珊瑚、挂链、缆线和支架与主体分开；不能把所有非透明像素都变成空气墙。按同一比例变换原画和主体轮廓，记录离散采样的近似范围，验证角色净空、固定敌人的落脚点及上/下绕行。资源清单分别记录整张源图、裁剪图和运行副本的路径与哈希，避免用同一个 source 字段覆盖不同来源。

## 图集与资源加载

打包时为线性采样准备间距和边缘挤出，按实际引擎设置检查 Clamp/过滤行为。具体像素间隔由缩放和采样决定，不把某一项目的 4 px 挤出、8 px 间隔当作通用要求。

保留稳定帧 ID、动画片段和来源清单。新图集接入前确认所有引用存在、矩形在纹理范围内、没有误用空帧。场景开始前预载必需纹理并复用 Sprite/特效节点；攻击、换枪和欢呼首帧不应触发临时加载。

章节切换先预载新资源并建立可用的新显示对象，成功后再替换旧会话；失败保留原会话与画面，重复点击合并为一次加载。切换时清空持续按键和触摸所有权，并保留加载期间发生的后台或竖屏暂停。隐藏节点不代表释放资源：先清理 HUD/角色 Sprite 和专属音频引用，再释放本章节创建的帧与纹理；共享图集单独保留，不能用全局释放误伤其他章节。验收至少包含正常 A→B→A、资源失败后重试，以及加载中切后台。

可取消的异步加载使用代号区分每次生命周期。在资源包回调、纹理回调、等待完成后的续体及失败处理处都检查代号；旧回调不能写新帧表、清空新加载的 pending，也不能释放新一轮正在使用的缓存资源。即使纹理 Promise 已完成，后续微任务仍可能晚于 release。用可控回调顺序模拟这些交错，再做引擎内真实卸载/重载；模拟检查与资源计数不能替代真机显存测量。

主包变大时先测量资源分布，考虑引擎支持的分包与预载，再决定压缩。无损重新编码要用解码像素比较证明；调色板量化、透明阈值处理、去噪或缩放都可能改变像素，不能统称“无损”。

保留完整源图和裁剪图，另产出有来源路径、源尺寸、运行尺寸及哈希的运行副本。按最终屏幕尺寸决定缩小比例：小型角色可以降采样，巨型 Boss 船体保留更多细节；不要将所有素材机械缩成同一比例，再放大到模糊。地形原画未完成可重复模块契约时，应先做可拼接主体或与画风一致的完整地形绘制；“碰撞方框里面贴几张小图”只能用于调试，不能作为成品地图交付。岩壁、海床、钢梁应各自形成可辨认的结构，局部装饰附着在结构上，不能把小图横向拉伸成整块地图。自然轮廓改变后，绘制与碰撞须消费同一轮廓数据；使用窄条矩形近似轮廓时检查误差、真实通路和已有敌人的支撑面。

## 资源检查工具

本技能的 `源码/scripts/inspect_sprite.py` 仅读取文件，输出 JSON 并用退出码表示成败：

- 0：所请求的检查通过；1：资源或清单检查失败；2：命令行参数错误。
- 默认输出实际尺寸、颜色模式、文件字节、SHA-256、透明/半透明/不透明像素数量。
- `--require-transparency` 要求同时有完全透明背景像素与可见像素。
- `--frames` 检查帧 ID、矩形范围、非空内容和锚点数值；允许框外锚点与帧矩形重叠，不推断动作语义。
- `--compare` 比较实际尺寸和每一个解码后的 RGBA 像素；文件 SHA 不同仍可能像素一致。

透明度统计不能证明人物白色没有被误删，矩形合法不能证明动作完整。仍需查看原图、接触表与游戏关键帧。

产出建议：原图、使用的提示词和参考图记录、帧/挂点清单、运行图集、预览图、检查结果。资源路径遵循当前仓库规范；不要把生成产物散落到新建的无关目录。
