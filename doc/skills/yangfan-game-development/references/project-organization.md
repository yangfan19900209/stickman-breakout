# 工程整理与清理

适用于把游戏源码、素材、运营、计划和进度拆开管理，以及清理历史工具与无用资源。沿用当前引擎和用户指定的目录语言，不因整理更改玩法或重新设计架构。

## 先记录，再移动

- 检查真实工作区和未提交内容。保存代码、运行资源、配置、依赖锁、文档与启动入口的逐文件清单；需要删除或改写的独有内容先归档，记录 SHA-256 并从归档重新读取核对。旧 Git HEAD 不能代替脏工作区快照。
- 将引擎根目录作为一个完整工程移动。Creator 的场景、脚本、运行资源和 `.meta` 配套迁移，创作原稿可以放在同级素材区；运营提交证据与游戏资源分开。生成缓存、依赖和构建产物不能误认成源文件。
- 提供明确旧→新路径映射。先核对移动后的原始字节，再改路径；移动中断时记录已完成批次，重新检查两端，不能盲目覆盖已有目标。Windows 移动和删除前核验绝对路径位于指定工作区，识别链接和被占用目录，保持原生文件操作在同一环境内。

## 引用决定去留

- 旧版本文件名不是删除依据。图集、测试夹具、动态资源表和备用呈现仍可能在使用；同时核对静态导入、场景组件 UUID、运行时字符串加载、平台分包及测试/生成工具引用。未开放的章节样段也不能自动当作废弃代码。
- 删除无引用的生成模块时，检查旧生成器，避免下次工具运行又把它写回。保留真正的回归测试；将一次性旧版本校验与固定版本封包脚本移出当前入口，留下恢复位置。
- 内容相同也要区分用途：可去重宣传工作副本，已经提交的材料快照和版本交付证据应保留独立语境。先用哈希证明重复，再选规范位置并修正文档链接。废弃设计候选与最终稿分开，保留用户纠正及选择依据。

## 路径适配与证据

- 分别处理引擎内相对路径、脚本工作目录、模块相对导入、素材清单、Markdown 链接、启动脚本和发布目录；不要做无边界全仓替换。Node 的文件 URL 使用标准转换，Python 的 `Path.relative_to` 无法表达兄弟目录，必要时用 `os.path.relpath`。
- 历史报告和归档清单保留原版本、原路径与哈希。消费者通过明确映射读取旧路径，不为让新脚本通过而重写历史证据。归档 ZIP 条目使用工作区相对路径，禁止带 `../`，恢复到新的空目录。
- Pages 等发布服务可能绑定固定目录。保留必要入口或明确迁移发布配置；移动源码并不授权发布或改动外部服务。
- 在新根目录执行类型检查、现有逻辑回归及实际构建；对受影响的资源入口进行浏览器/平台运行检查。比较现用图片、重要源码、固定交付与体验锚点的字节，检查文档链接和生成输出位置。源码/原稿不变仍不能直接宣称新根目录可构建。
- 根目录给出短导航；计划写目标与完成标准，进度写实现状态和验证边界，固定交付写版本及包来源。工具不可用时明确哪些处理流程未执行，不用未运行的官方校验器标记“通过”。
