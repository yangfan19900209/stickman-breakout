# 物理与战斗

## 状态放在哪里

保持可独立运行的模拟层：会话负责推进时间和系统调用，玩家/武器/敌人各自持有权威状态，渲染层读状态并选择帧，平台层处理设备能力。能在不加载 Cocos 场景的情况下复现伤害、碰撞和攻击时序，才容易把表现问题与规则问题区分开。

固定步长由会话或驱动层统一推进，渲染帧可以有多个模拟步。限制后台恢复后的累计时间，暂停时清理积压输入。不要在多个层中各自扣弹、统计击杀或推进同一攻击计时器。

将长按控制跳高改为轻按满跳时，先区分蓄力起跳和松手截断上升：后者只需在指定跳跃阶段取消松手削速，不要加大所有起跳速度。用户要求二段跳不变时，保留空中次数、重新按下边沿、二段松手控制和落地恢复；土狼起跳与落地缓冲归入第一跳。比较一次模拟步的轻按与持续按住的峰值，并回归下跳、低顶和二段跳。试玩输入策略若依赖提前松手落地，也要改为真实可用的闪避动作，不能调低伤害来让旧策略通过。

## 支撑面、箱体和残骸

按对象类型检查：完整箱体 → 破碎后的大块残骸 → 小碎片 → 掉落物。它们可能有不同生命周期，但都不能靠固定地面高度维持位置。

1. 以当前地形、移动平台和仍存活的实体碰撞框重建可支撑表面；排除对象自身及已经移除的旧实体框。
2. 记住上一帧脚底、支撑物 ID 和支撑面的位置变化。平台移动时，先按支撑变化携带对象，再重新检查有效接触。
3. 向下移动时遍历实际跨过的表面。对于世界坐标 Y 向上的项目，候选条件近似为：水平重叠，`previousBottom >= top` 且 `nextBottom <= top`；选择候选中最高的表面。其他坐标约定相应转换。
4. 悬挂箱体可在触发前保持悬挂；一旦释放，进入真实重力和碰撞流程。平台被破坏或横向移出支撑范围后，原支撑必须失效。
5. 销毁只产生一次掉落、一次碰撞失效和一次奖励。视觉残骸可以继续更新位置，但不能继续冒充完整箱体挡路。
6. 小碎片采用重力、反弹和停止条件；初始嵌入修正只处理从表面上方产生的碎片。平台下方的碎片不能被纠正到平台顶上。

射断绳索后落下的整块桥面也要检查下方完整覆盖范围内的真实支撑，不能始终停在预设地面高度而穿进永久石墩。选择下降扫掠首先触及的最高顶面，承托乘员的位置变化使用同一个实际位移；支撑移动或被破坏时跟随或重新下落。把可破坏道具改为永久障碍后，特别回归这种组合场景。

显示与碰撞使用同一份资源坐标契约，但不要求整张可视包围盒等于实体框。提环、把手、散石、草叶等突出装饰不能抬高站立面；在源图中标注真正的承托顶线及主体左右边缘，按相同世界比例生成实体。测试应核对脚底接触实体顶线，而非只断言两个包围盒相等。受损帧可以增加裂纹，但主体轮廓不能随破碎图的空白区域突然收缩；残骸几何另行定义。

需要覆盖：多层平台、支撑消失、移动平台携带、边缘跌落、箱上箱、地形台阶和低矮通道。低矮通道要验证两个方向，尤其是走到出口抬高的台阶后，头部仍有净空。

## 推进与镜头边界

单向推进关卡需要限制回退时，由关卡保存最远实际推进位置与单调更新的后方边界，仅约束玩家。将边界用于本步水平位移，再按落点解析垂直碰撞，让行走、空中和受击共用规则；不要只在输入层禁左或事后传送。用当前关卡的躲避、跳台与补给距离选择退路，Boss 战可保留整片竞技场与入口缓冲；例外结束时只随新的实际推进收紧，不能把边界推到玩家身上。若退路应止于画面边缘，让同一后方边界成为镜头最左位置：镜头先停止，角色继续走到可见左沿；校验角色半宽、镜头缩放与平滑，不让物理墙落在画面中部，也不在缩放后把玩家推出画面。Boss 活动边界随推进收紧时，不得把静止身体或已经锁定的炮口强推到新边界，应允许它依照正常运动追上。界面提示限制，重开清零。物理几何的双向测试与正式游玩的回退限制分别验收，整关自动输入策略也须遵守同一边界。

## 前景结构与移动平台的实体规则

先按对象类别明确阻挡范围，再确认梁体、承重柱、栏杆和背景导轨是否位于可交互平面。不得把某一类平台的阻挡要求推广到所有架子；用户的新指示覆盖旧的结构约定。用户选择无柱悬空平台时，同步移除柱子画面与碰撞，可采用从下方跃上、从上方落地承重的单向台面；固定台与移动台沿用相同视觉语言。只有明确要求实体阻挡的部件才由相同结构尺寸生成碰撞，装饰不自动变成空气墙。

固定可选平台应分别验证“站立从下方双向走过”和低层入口“一次正常跳跃上台”。少量高层逃生台可从相邻低台上跳，须按真实水平间隔和高度差验证两侧可达，不能用二段跳或自动驾驶反复调整起跳点代替容易到达。降低台面时同步检查梁厚和角色可见头顶净空，移动敌人、箱子及补给至新支撑面；不要只降低整座结构却把下层压成蹲行通道。动态台另验证完整往返、正常上台、连续载人和主动离开。

组合 `platformer`、`level-design` 与 `input-systems` 加入下跳时，消费“向下＋跳跃”的一次按下事件，只暂时忽略当前承托角色的单向表面，直到脚底越过其下沿；同高度拼接的承托面共同处理，实体地面或掩体不参与穿透。下层平台保持碰撞，持续按住不能自动连穿多层，不残留跳跃缓冲或土狼时间导致反弹。键盘与触屏复用动作，按钮提示读取实际可下台状态；覆盖叠台、边缘、其他角色不受影响、重复按下、暂停和重开。

新增高低台后还要带着真实道具与攻击验证跳跃连接：射落的悬挂箱、平台上的奖励箱和爆炸冲量都可能改变可用落点，空场物理测试不能证明交战时路线清晰。将干扰连接的道具移到合理位置，不通过试玩传送或关闭道具碰撞绕过。独立地形测试应重置或隔离上一用例的推进边界，避免无序平台列表让较早的测试出生点被旧进度推走。

把开放平台改为带实体柱的结构时，同时检查柱间是否成为封闭区域：地面敌人、补给和出生点不得留在不可到达的区域；扩大掩体后也要重新检查出生点与物体重叠、出口间距。既有开放通道的物理回归可以保留为明确的测试夹具，实际关卡另用新规则验证双向通路。

实心升降台除了携带脚底接触的乘员，还要处理下降碰头、上升托起及乘员碰到上方横梁。按实际接触限制本步位移并停止/反向，随后同步立柱高度与乘员位置；不要先无条件移动角色，再让下一帧修正嵌入。覆盖侧面阻挡、跳跃落台、连续载人、上下挤压与重新离开，并用真实输入检查起跳位置。

单向移动台不能沿用实心台的下降碰头反向逻辑，否则站在下方的玩家或敌人会截断行程，造成台子反复折返。只携带已接触台面的乘员；角色上跳穿过台面时不被提前吸附或重置跳跃，下降时再承托。乘员头顶存在真实实心天花板时仍要防止挤入。回归必须包含“有人长时间站在台下仍到达上下端点”，不能只测空载行程。

## 软质掩体的破坏

沙袋等软质堆叠物用受击裂口、袋块分离、沙粒与短尘雾、重力落地、停留后淡出表现破坏，不把完整图纵向压扁当成动画。检查所谓 broken 帧是否实际指向完整图；名称不等于资源内容。飞散的大块需要完整闭合的破口轮廓，直接把堆叠图矩形切片会在旋转后暴露生硬切边。

残片保持源图比例，碰撞半径与显示高度共用尺寸，落地后停止旋转并衰减水平速度；支撑移动时随动，支撑消失后下落。破坏瞬间移除完整掩体碰撞，残片仅呈现不挡路。限制大块、沙粒和尘雾的数量与寿命，复用现有粒子池和预载图集；用命中、散开、落地、淡出的连续截图检查，不能只验证最终对象消失。

## 拾取与装备原子切换

让武器系统统一拥有装备 ID、弹药、射速和切换状态；玩家画面、HUD、掉落物通过它读取和更新。

- 拾取前先确认目标装备可呈现。所需资源缺失时保留旧装备和掉落物，避免扣除道具后玩家空手。
- 拾取成功后一次性切换状态；旧枪体、枪口闪光和临时节点同步失效。
- 手动切刀保存原武器状态，切回时保留其弹药。明确冷却是暂停还是继续，不要意外重置后允许连续超速发射。
- 满血不消费血包，治疗不超过上限；弹药上限与溢出策略同样需要明确。
- 使用拾取半径帮助操作，但保持道具实际位置、阴影和支撑一致。视觉放大不能变成穿墙拾取。
- 图标必须表达实际补给种类，不能把子弹箱画面映射成手雷。满额或当前装备不适用时保留道具并给出短提示，避免表现成无响应；切刀时的补弹通过同一武器状态所有者更新收起的枪，保留冷却。掉落物采用自己的支撑引用和顶面位移，覆盖移动台上下行、支撑消失及对象池复用。

## 近距离用刀与弹药保护

区分“显式切到刀”和“持枪时上下文近战”。后者特别适合近距离安全箱子，危险爆炸桶是否自动近战由游戏设计明确决定。

刀击分为前摇、有效期、恢复期；一轮挥击对同一目标最多结算一次。检查朝向扇区、距离和中间掩体，冲刺位移仍经过正常移动碰撞。

挥刀光效消费模拟层的有效标记和当前角度，不用另一套动画时长反推。上下文快刀和显式连招的前摇可能不同；逐个验证刀光、刀尖与伤害时刻。完整人物图已经包含刀刃时，只补刀光和命中星芒，不再叠一把刀。受击选择优先于举枪、游泳和持武器分支，若采用收枪后仰帧，同一时段也应禁止发弹，不能从空手图里出弹。

按住攻击拆箱时，保护的是**整次按压意图**，不是单个有效帧：

```text
开始按住攻击 + 前方安全箱体可近战 → 进入拆箱按压状态
前摇 / 挥刀 / 恢复 / 箱体消失 / 自动换枪 → 仍禁止发射消耗型弹药
松开 / 明确切换模式 / 死亡 / 改为向上瞄准 / 离开有效范围 → 清除状态
```

否则箱子刚碎、刀刚收回或自动拾取火箭筒的瞬间，同一次长按会浪费一发火箭。验证长按跨越销毁和拾取的全过程，而不只是第一刀。

保护状态还必须保存实际拆箱目标，离开其近战上下文后释放；单独的布尔值只在松手时清除，会让长按攻击的玩家离箱很远仍只能挥刀。二维游动距离使用身体与箱体交互点；同时验证“原地持续按住不误耗弹”和“移动离开后恢复枪击”。

## 组合输入与低姿态移动

“下＋跳”等组合动作在普通跳跃缓冲之前解析；地面触发失败或冷却中也消费该组合的按下意图，避免松开下方向后补出一次意外跳跃。空中单独决定是否保留二段跳，不把地面滑铲规则套进二维游泳。短按沿、持续按住与冷却分别持有，长按不重复触发。

滑铲使用完整低姿态原画和对应碰撞体，位移仍经过原有扫掠。检查起动作的头顶空间、迎面墙/箱体、台边落下和恢复站姿的净空；结束时头顶仍被挡则保持低姿态。受击、死亡、重开要取消动作，暂停要冻结计时。回归同时包含键盘组合与两个独立触点，且在空地展示动作、在障碍旁验证停止，不能把正确撞箱误报成输入失效。

## 枪口、弹道与命中

完整持枪角色帧的枪口来自原画挂点。以角色脚底为共同原点，转换裁剪偏移、世界缩放、Y 轴方向与左右镜像。视觉发射点和物理弹体生成点使用同一变换。

- 瞄准姿势、实际炮管方向、炮口与初速度共同响应输入。完整原画只有平举动作时，应补齐举炮帧或使用原本就支持独立武器转动的结构；不能把“先水平出弹再拐上去”当作向上瞄准的默认修复。只有玩法明确需要制导转向时才使用独立的有限角速度。
- 弹体从生成开始参与碰撞。不得先传送到墙外或暂时关闭碰撞来修正画面；跳台是否挡弹由明确的玩法规则决定，不能仅因角色可站立就推定挡弹。
- 炮口可能伸进或越过薄掩体；首次扫掠从实际筒身内部/后口沿轴线到炮口和弹头，避免跳过掩体。竖直炮筒不能沿角色中心到炮口做水平扫掠，否则会误撞侧墙。
- 高速弹体用前后位置的扫掠命中，墙体与敌人取最早接触，避免穿过薄墙后才伤害敌人。
- 追踪要有限转向、有效目标和必要的视线判断；目标消失时明确退化行为。
- 原画如果画有飞出的弹体，不要再叠加一个同位置的模拟弹体。优先使用干净的完整角色帧配真实弹体。
- 池化复用必须重置命中集合、寿命、目标、转向进度、伤害来源和残留特效。
- 实体弹丸出筒时只显示已露出的部分，尾烟等弹尾离开炮口再产生；后喷口特效使用同一筒轴和镜像变换。圆环等完整波形按自身中心和传播方向绘制，不能套用弹头锚点/露出裁剪，否则首帧会变成半环。验证首帧，而非只看最终飞行方向。

同类弹药以武器家族统一原画、完整尺寸、露出长度、尾烟位置和接触半径，敌我归属不应各维护一套尺寸。需要强化 Boss 弹体时使用明确的等级倍率，绘制与模拟共同读取；清理旧外观标记优先覆盖家族规格的分支，对象池复用也要重置等级。验证实际 Sprite 的尺寸及完全出筒后的画面，不能只检查配置值或因一条试玩路线没遇到某种弹药就略过它。

自动瞄准提示读取实际目标和炮口射线，不另写一套“最近敌人”选择。允许开火前预览时，瞄准更新不能只放在按住攻击的分支内；死亡、遮挡或出屏立即撤销旧锁定，换目标的防抖延迟不能让失效准心继续挂在敌人身上。身体中心到目标的角度不一定等于偏置炮口到目标的角度，需按实际持枪帧求解并验证两者共线。准心区分已锁定和无目标的射击方向，遮挡检查同时覆盖身体到炮口、炮口到目标。视口包含纵向跟随和 HUD 占位时，模型测试也必须更新真实镜头，不能固定旧岸上镜头后误判水下锁定失败。

将前方锥形瞄准扩展为近距离全方向锁定时，保留范围、可见性、遮挡和原目标稳定性约束；大型 Boss 从玩家所在侧选取有效船壳/部件点，不能固定瞄准远侧船首。偏置炮口的角度求解应先由目标方位确定镜像分支，整个求解与渲染共用该分支；每次迭代都按试算角度重新翻转原画，可能在正下方来回振荡，增加迭代次数也无法消除。回归覆盖两种身体朝向、八个目标方向、真实炮口射线、失锁，以及从 Boss 四周发射后实际命中。

锁定放大/收拢反馈由有效目标的身份变化触发，沿可暂停的模拟时间推进；不能每帧重新播放，也不能改为一套视觉目标选择。失锁立即清除，重新捕获或换目标再播放，暂停冻结进度。准心按镜头缩放补偿屏幕尺寸，并用明暗描边配合既有强调色；实际手机视口验证获取、稳定跟随、换目标、遮挡、目标死亡和暂停，而非只验证半径公式。

用户按“几次击败”定义普通敌人耐久时，先明确目标类别、单次命中伤害、护盾是否包含在总生命内，再验证真实弹体碰撞。不能只调初始血量，遗漏后半关加血、穿透衰减或爆炸结算；也不能全局降低弹丸伤害，连带改变 Boss 战。回归至少包含普通、护盾、Boss、穿透后续目标和一次爆炸只结算一次。单位点血可限定在普通敌人受伤入口，特殊目标继续沿用独立规则。

统一弹药外观不等于统一伤害。多个敌人共用火箭/炮弹原画时，逐个检查实际发射入口；若设计要求固定伤害，在共同弹体初始化入口按归属与家族集中约束，保留普通子弹和 Boss 受伤规则。爆炸回归走实际碰撞、爆炸队列和目标受伤链，覆盖直击、撞墙溅射、半径边缘、盾牌正反面与重复结算；同时核对距离衰减和生命值取整后的最终扣血，不能只断言发射配置或直接调用目标扣血。

按玩家、普通敌人和 Boss 分别约定伤害时，先列出攻击者、目标类别与弹种的对应表。爆炸队列显式携带弹种或来源，不能用“伤害大于某数”推断火箭，否则数值调整会误切倍率或斩杀规则。普通敌人斩杀应作用于真实生命与护盾破碎流程，Boss 保持固定扣血；同一颗穿透弹先后命中不同类别时分别结算，部件与本体仍只扣一次本体血量。减少获取点后，自动试玩应正常寻找仍存在的补给并节省有限弹药，不能靠旧掉落、增加生命或降低伤害维持旧路线。

水下向前投掷与陆地抛物线分开定义。投掷点沿实际身体/手部和瞄准方向产生，首段检查近身薄墙；需要水平保持时只用同方向水阻，不能遗留向下重力。碰撞或引信到期只入队一次爆炸，长按沿、库存消耗和池分配成功在同一事务中处理。覆盖左右、斜向、贴墙、长按、池满、暂停与重开，手机按钮也要走相同入口。

向上发射测试先检查头顶几何及其挡弹规则。需要跳台通弹时，弹体碰撞、追踪视线、敌人开火视线和射线武器共用同一判定，角色支撑、向下穿台和手雷实体碰撞各自保留。分别验证上下射、左右朝向、敌我归属、薄实体掩体仍能挡弹。视线放开不等于射角足够：敌人在高台上瞄不到脚下玩家时仍要移动接敌，不能停着向错误高度开火。

## 地面敌人的跨障碍追击

横版追击不能只按目标横坐标设置速度，或撞墙后反复使用同一个小跳。先检查当前脚底、阻挡物顶面、目标高度和可落脚范围，再依据重力、起跳速度与水平速度筛选可达表面；用临时身体调用同一套实际移动碰撞验证弧线和净空。局部平台较少时可采用有限候选与冷却，不必引入整图寻路；复杂多层路线再按引擎能力扩展。移动表面的目标保存相对位置，真实角色仍通过重力和碰撞完成移动，不吸附到规划终点。

从平台追向下方目标时，离台判断要包含身体半宽：中心越过台边但碰撞体仍被承托，立即转向目标会在边缘来回卡住。出生巡逻范围只限制巡逻，不应无条件限制战斗追击；原来驻台的敌人也要覆盖离台、跨掩体和重获射线。近战在真实掩体阻隔时先接近或跨越，不能不断对墙发动冲刺。

导航与攻击承诺分开：跳跃可有预备、腾空、落地恢复，已锁定的射击和冲撞不因目标换层而随时取消或转向。空中转身保留兵种原有反应延迟；瞄准、恢复、失活及空中死亡也要继续处理重力与支撑，避免某个状态提前返回后悬停。不会通过的高墙或低顶通道应拒绝跳跃，而不是反复原地跳或穿透。

组合 `game-ai` 的状态与路径方法时，用双向掩体、目标上台/下台、脚底仍搭台边、驻台敌人离开出生区、空中死亡和攻击锁定建立行为回归，再验证真实关卡的几何。浏览器的主动引诱上下台用于证明追击能力；持续火力下的招式覆盖、整关输入通关和真机体验仍分别记录。

## 敌人攻击的可读性

护盾兵的总生命与盾牌耐久分别定义。用户要求“比普通兵多几点血”时，先按实际弹丸伤害确认总击杀次数，不能无意叠加额外护甲血条。若盾耐久只是这些命中的视觉阶段，同一次伤害同时推进生命和破盾阶段；明确正面、背面、近战与爆炸的规则。破盾作为一次性事件由会话消费，存活角色切换无盾姿态，碎片动画独立于角色死亡继续播放。陆地碎片使用真实地面/平台承托；水下按介质定义散开、浮沉与消失，不照搬地面落点。覆盖致命一击、重复伤害、平台移走、暂停和重开；浏览器同时核对实际绘制帧与破盾后剩余生命，不能只检查图集存在。

统一武器伤害时，沿发射、碰撞、目标受伤、穿透递减和 Boss 特殊倍率逐层核对；只修改发射值可能被目标分支再次覆盖。用同一伤害规格验证普通兵、盾兵、连续穿透目标和 Boss 的实际扣血。爆炸命中大体型目标时，按实体最近点和真实阻挡判断，不能因其中心点超出半径而让已经接触的炮弹无效；保留同次爆炸的去重。

用“预警 → 锁定 → 发射/命中 → 恢复”组织攻击。需要锁定的攻击，在预警阶段保存方向和落点，不能在出手瞬间无预警转身命中玩家。

调整“攻击更密集”时，分别约定单次弹量、同轮连发次数、独立攻击轮次、轮间恢复和重新瞄准，不能直接等同于提高射速或散射。用户要求每轮一发时，同时清除初发和延迟补发分支；不同方向可来自恢复期换位，每轮都重新走完整预警。统计真实发射时刻与弹数，并检查预警线和实际弹道一致，避免仅修改配置后仍由旧队列补发。

限制 Boss 全场增援总数时，记录本场累计召唤数，不以当前存活增援数量作为补召额度。换阶段、增援死亡与反复进入战区不能刷新总量；重开才清零。新增增援复用普通敌人的创建入口、预警和恢复规则，出生位置避开玩家和实体障碍，且同步关卡说明中的固定敌人数与额外增援数。

| 类型 | 应暴露的机会 | 常见错误 |
| --- | --- | --- |
| 步枪兵 | 短连发后的换弹空档 | 每帧跟随瞄准，玩家没有躲避窗口 |
| 近战/盾兵 | 明确前摇与有效方向 | 隔墙命中，或反向经过仍受伤 |
| 炮击 | 对应实际地面的落点预警 | 所有炮弹共用一个地面高度 |
| 激光 | 清晰蓄力、固定发射源、可读射线 | 预警已造成伤害，视觉被挡而伤害穿墙 |
| 多阶段 Boss | 阶段转换与攻击后的喘息 | 仅增加弹量，攻击叠加无避让路线 |

不同敌人应在射程、移动、预警、覆盖区域或恢复时间上产生不同选择。新增模式时同时定义“玩家如何识别和避开”，并在普通移动速度与可用跳跃能力下验证。

还要检查模式能否在普通战斗中出现：如果基础武器的击杀时间总短于接敌等待加预警，代码里增加多种模式仍会表现成一批不会攻击的靶子。按玩家实际带到遭遇点的装备、弹药和手雷持续施压，检查爆炸增伤与连锁伤害，记录第一下受伤至击破的时间和实际出招次数。暂停开火、等待轮招的演示只能证明状态可达，不能证明正常交战能看到多种模式。结合射程、接敌时机、主动换位与适度耐久调整，不靠取消预警或单纯堆血；冲撞终点应留出后续换位空间，避免穿过玩家后被活动边界卡住。限制同时处于预警/攻击的敌人数；敌人离开激活范围时释放攻击占用，防止远处旧状态阻塞新遭遇。模型验证时序，浏览器记录实际交战，两者分别报告。

受击延迟必须有每轮上限，不能每一发命中都累加预警时间，形成永久压制。提高后半关压力时优先调整敌人协作名额、活动高度、恢复窗口及弹体速度，保留锁定方向和可读前摇。试玩策略要等已发射弹体通过后再返回原来的高度；敌人进入恢复状态不代表它的子弹已经消失。

持续追击型 Boss 应将“已开战”与“玩家当前仍在出生战区”分开。首次进入后保留战斗激活、受击和血条直到击破或重开；离开旧入口不重置前摇、血量或锁定攻击。追击目标与实体移动分别处理，恢复窗口之后再追赶，不移动已经锁定的发射源。导航候选除了面前掩体，也要检查掩体上方的单向台面：真实碰撞可能先让身体落在上层，只验证窄掩体会错误判定无路。用实际碰撞器模拟候选轨迹，验证宽体 Boss、普通兵和上下台。下台路径要包含当前移动边界和玩家的退让空间：最近出口无法容纳完整身体时，选择支撑面的另一侧；保持下台与地面战斗使用相同的退让距离，防止落地后持续挤压屏幕边缘的玩家。还要覆盖先落在箱子上再落地的连续支撑，并在正常接触伤害下验收。按节流计时重规划。

把原地 Boss 改为可移动时，检查所有外部位移来源，包括弹丸击退、爆炸击飞、近战冲量与移动支撑。旧实现可能一直忽略速度，接入重力后才暴露“重型载具被掀飞、瞄准期间冻结在空中”。按对象明确冲量规则，保留伤害；步态按碰撞后的实际位移推进，预警锁定和持续射线期间不得移动发射源。回归要包含炮弹/爆炸命中、撞墙、停步以及脚底落地，不能只验证自行巡逻。

放大 Boss 后，移动边界需按新身体宽度保留玩家的退让通路；仅把中心限制在场内仍可能将玩家挤在边缘。冲锋锁定终点，跳砸锁定可达落点并在真实落地时结算，空中死亡或离场取消后续伤害但继续重力。阶段组合用不同应对动作衔接，每个后续攻击仍给独立预警；连发的最后一发之后保留恢复窗口。结合 `game-ai` 的状态承诺与 `game-feel` 的预警方法，用实际战前库存施压验证持续战斗，再分别记录模型与浏览器证据。

提高 Boss 压力时，先量测持续火力下实际出现的攻击，再调整换位、恢复和有限连射。跨血量阶段保留攻击游标，避免阶段更换与取模共同跳过特色招式；部件销毁时跳过对应招式并取消尚未发出的追击弹。预警早段可跟踪，后段必须锁定并给出完整避让时间，扇射预览覆盖实际弹道范围。制导弹可限制追踪时间和在场数量，避免无限追尾。完整通关检查与主动停火观察全部招式分开记录；测试操作也应选择边界内有空间的躲避方向，不能为沿用旧策略而降低游戏伤害或伪造生命值。

缩小宽体 Boss 来恢复换向退路时，同步原画、受击框和炮口比例；验证高台到身体另一侧的完整轨迹，不能只比较最高点是否超过头顶。越过整个身体所需的水平时间，可能长于脚底高于伤害范围的时间；分别记录普通跳和二段跳是否可行，并在正常接触伤害下双向验证。二维游动的大体型敌人则按完整上下边界保留可绕行通道，移动用船体扫掠并避免推挤玩家，预警和持续开火期间固定船体位置。

突进的触发距离必须与真实行程相容：匀速时检查 `速度 × 有效持续时间 + 接触半径 ≥ 锁定距离`，有加减速则积分实际位移。分别验证射程近端、远端、斜向、静止目标、锁定后的侧向闪避，以及中途撞墙。使用受碰撞限制后的前后位置做扫掠伤害，不能拿计划终点穿过掩体结算。预警前段可跟随目标，后段明确锁定；出手时不再追随玩家的新位置。

二维游动的宽体敌人绕行时，按完整身体扩张真实障碍并缓存局部路径；出生巡逻范围不应反复夹回正在追击的身体。绕过障碍途中首次恢复视线，不一定已经获得有效射击位置：保留绕行阶段直到身体和攻击高度满足条件，再恢复保持距离，避免两种目标交替造成原地摆动。路径不可达也缓存失败并节流重试，不能因路径数组为空而每帧重做搜索。实际位移始终经过原有碰撞；用真实沉船/岩壁、超出旧边界的追击、锁定后的冲撞和完全无路情形分别回归。

敌人躲避属于有代价的移动状态：只感知近处且将相交的可见弹体，经过反应延迟、地形通行检查后短移，设置冷却和恢复。侧向受阻时可评估斜向候选，用完整身体沿同一碰撞路径试走；只检查目标点或中心线通畅，不能证明整个身体可通过。不能读到玩家按键就瞬移、自动无敌，或随时取消已经承诺的攻击前摇。增加敌人总数时同时检查同屏攻击名额、在途敌弹上限与实际出现的模式；不要把更多敌人等同于更多弹幕。

装备 ID 同时决定敌人持枪原画、枪口变换、弹体家族和射击节奏，避免画着鱼叉枪却发射无关光点。同一武器在敌我两侧保持共同轮廓/尺寸，以少量填色或纹样区别归属。角色攻击用姿态、锁线、发射和恢复表达；按固定原画比例选帧，不能为了强调攻击而将整个人物忽然放大。

将人形小 Boss 改为载具时，除了原画必须同时替换移动占地、可受击船壳、瞄准中心、发射挂点与冲撞扫掠形状；不能继续沿用人形窄碰撞盒。固定船首炮口用船体对准、有限转向弹或明确的扇射覆盖，不让船体水平却任意角度发射。多管齐射从各自实际炮口产生弹体并独立检查墙体遮挡；沉没等死亡演出单独计时，奖励与死亡事件只结算一次。用有限状态组织预警、锁定、攻击和恢复（可参考 `game-ai`），分别验证能命中、可闪避、会被墙挡住及普通输入能完成遭遇。

## 章节切换与二维游动

二维实体移动与弹体命中不能直接共用“端点接触也命中”的线段判定。角色恰好贴着甲板/墙面时，只阻止进入实体的法向分量，允许沿面滑动和向外离开；垂直于当前移动轴的投影需区分严格重叠与仅接触。否则起点命中时间为零会让左右、上浮等所有方向都被锁住。对真实初始嵌入做小幅、最近合法边界修正，并检查整个相邻碰撞体并集，不能用大范围传送或关闭平台碰撞补救。

回归覆盖四个面上的切向/离开/进入、角点、极小嵌入、快速推进和实际出问题的平台。整关通关不能替代贴边检查：自动路线可能一直从平台上方通过，从未触发零距离接触。

地面与水下运动规则差异较大时，保留原会话的状态所有权，为水下建立独立会话；共享输入、碰撞算法、伤害接口、镜头和胜利时间线，避免把第一关全局重力或跳跃规则改成水下规则。输入层保留带正负号的纵向摇杆值，由当前章节解释为瞄准/蹲下或上浮/下潜；二维移动先限长，防止斜向加速。

要求将一关的修复推广到另一关时，按弹体规格、敌人状态、镜头边界、补给与伤害路径逐项核对真实调用。共有规格复用同一来源，移动和攻击的章节差异分别保持；不要把“同一引擎”当作两关共享同一会话的证据。基础弹增伤必须限定目标与弹体家族，分别检查船体、模块和爆炸去重，不应连带强化对普通敌人的伤害。

进入章节先完成资源预载，再一次性切换会话与画面。并发点击只加载一次，失败恢复原状态并允许重试。暂停、退出、重开与跳过入场都要清空旧输入；跳过演出到达的装备、位置、镜头和危险启用状态应与自然播放一致。

水下整个人物旋转瞄准时，原画身体枢轴、枪口和初始速度使用同一旋转/镜像变换。最后一发有限弹药发射后即使逻辑装备退回基础武器，也要让本次发射帧保留原武器姿势和炮口；不要让回退顺序改变已经发生的射击。可破坏 Boss 多部件共享总血量时，一次爆炸按船体去重，同时独立结算部件损坏。

## 保留战场的原地复活

将复活实现为独立于整局 reset 的恢复操作：先在实际碰撞几何、完整站立/游泳身体、当前交战区和已到达范围内找到合法点，再一次性消耗额度与恢复身体。活动平台锚点保留支撑对象引用与相对位置，使用时重新校验；支撑已消失、低顶、敌人/Boss 实体覆盖或无合法点时不扣次数。不能只检验脚底中心或固定高度。

保留敌人和 Boss 血量、装备弹药、已消费补给、一次性掉落和战斗统计；危险清理只撤销当前弹体、延迟爆炸、连发队列、冲撞和激光，避免调用整场 reset 复制资源或复活敌人。玩家恢复方法单独清理死亡计时、近战/投掷、冲刺、下台忽略面和输入边沿。

准备阶段作为可暂停的会话状态冻结模拟，保护时间从恢复操作后开始消耗；后台返回不能自动解除暂停。驱动层须推进该状态，并在准备结束时再次清理按住的输入，防止准备期间的按键积压成第一帧攻击。验收同时覆盖两次死亡、暂停准备、残留伤害队列、资源守恒与正常输入继续游玩；模型测试和真实构建操作分别留证。
