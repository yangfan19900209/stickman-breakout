# Mac 独立开发入口适配 · 2026-11-14

范围：为现有 1.0.7 工程添加 Mac 命令行开发、构建、测试、打包和上传入口。未修改玩法、运行资源、版本号、依赖锁或 Windows 构建/上传实现，未覆盖历史固定包或体验锚点。

本记录保留第一阶段适配的验证归属。后续上传前已将预览和结构检查进一步迁入 `scripts/mac/`，恢复原共用脚本；当前入口与 Windows 保留核对以 [Mac 环境独立记录](../mac-environment-20261114/README.md) 为准。

## 已实现

- 根目录 `Mac开发.command`：可双击菜单，也可带命令参数运行；含中文/空格路径，参数不经过 Shell 二次拼接。
- `源码/scripts/mac/`：项目独立 Node/npm 初始化、环境诊断、代码检查、Web/微信串行 CLI 构建、Web 试玩、浏览器冒烟、固定微信包和开发版本上传。
- 构建读取既有配置，要求 Creator 3.8.8、完成日志、新入口、无缺失类，再执行原后处理。独占锁、输入快照和产物哈希阻止把旧输出当成本轮成果。
- 固定包复制有效载荷，生成 ZIP、更新说明与清单，再解压核对文件哈希。上传只使用当前固定包，并检查构建/测试与源码一致；通过微信开发者工具自带 CLI 上传开发版本，不送审、不发布。
- 预览的浏览器启动命令按系统选择；完整验证使用独立临时端口，避免误测另一个占用 4190 的服务。
- 新增 `check:project -- --source-only` 模式，单列 Git 明确忽略的历史本地材料；原完整归档检查默认行为保留。

操作说明：[Mac 开发入口](../../../doc/MAC-DEVELOPMENT.md)。此前同机编辑器构建/微信启动的证据在 [mac-20261114](../mac-20261114/README.md)，两次验证边界分开记录。

## 未完成与真实阻塞

1. 本机尚无完整 npm 环境，项目依赖是临时离线副本。`mac:doctor` 正确返回未就绪；初始化器已经实现，但当前受限执行环境的 npm 网络不可用，因此未实测下载与 `npm ci`。
2. 此前受限执行进程启动 Creator，在进入构建前 `SIGABRT`；系统崩溃栈指向 AppKit / `_RegisterApplication`。普通终端尚未对比，不能把“受限进程失败”认定为“Mac 必须手动打开编辑器”或已证明的游戏代码问题。
3. 电脑控制工具明确拒绝操作 `com.apple.Terminal`。未通过 Finder、其他终端或系统脚本绕过该限制，因此普通终端的初始化/完整构建需要用户启动入口。
4. 独立临时目录中的最小预览夹具在绑定 `127.0.0.1` 时被执行器拒绝（`listen EPERM`），尚未执行 HTTP 内容检查或浏览器全流程。没有完整 Mac CLI 构建回执，故没有把现有 GUI 包登记为新的 Mac 固定交付，也没有执行微信开发版本上传、送审或发布。微信模拟器完整输入和 iPhone / Android 验收仍待进行。

下一步：双击仓库根目录 `Mac开发.command` 选 `1`，在普通终端完成初始化、检查、双构建与固定包；生成的逐轮记录位于 `开发进度/验证记录/mac/`。如失败，入口会停止并保留具体阶段，不把之前生成的文件当作成功。构建不需要先手动打开 Cocos 窗口。

本轮尚未证实普通终端中的 Creator 根因与修复，相关猜测只留在任务记录；现有通用构建/交付规则已覆盖哈希与验证边界，不重复添加技能条目。
