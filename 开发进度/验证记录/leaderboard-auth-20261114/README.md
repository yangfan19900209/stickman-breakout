## 反馈和已确认问题

用户真机最初显示“你暂未允许微信朋友信息”，设置页却没有朋友信息开关。代码把所有 `authorize.fail` 都当作拒绝，且在异步查询后打开设置；设置返回缺少 scope 时仍重复引导设置，前台事件还可能重置成功结果。

第一轮修复通过 534 项逻辑测试并生成 `1.0.7-好友榜修复-20261114`。随后用户反馈“好友榜服务暂未就绪”：这是新代码对配置类错误的归类文案，不是微信原始错误。当时尚未取得实际 stage、errno、errMsg，无法确认具体后台问题。

用户进一步要求微信原生授权弹窗。当前版本不再注册 `onNeedPrivacyAuthorization` 或显示自绘隐私确认，而是在用户主动点击后调用 `requirePrivacyAuthorize`，成功后再查询/申请 `scope.WxFriendInteraction`。已同意用户可能直接成功，不保证每次重新弹窗；平台配置错误也可能先于弹窗返回。

## 当前修复

- 区分未知权限、明确拒绝、接口/配置错误；只在实际 scope 为 `false` 时提供设置入口。
- 设置入口在原始点击内直接调用，返回缺少开关时允许重试，避免反复进入无开关设置页。
- 打开榜单和返回前台复查权限；保护原生窗口期间的请求、异步异常与关闭后的迟到回调。
- 使用微信原生隐私流程，拒绝仍保留个人纪录和单人游戏。
- 正式构建也输出 `[好友榜]` 诊断，仅含阶段、分类、错误码及截短错误说明，不输出好友资料或成绩。

改动位置：`源码/assets/scripts/platform/SocialBridge.ts`、`源码/assets/scripts/ui/RecordsPanel.ts`，以及授权和社交回归测试。未修改关卡玩法、美术或 Windows 构建脚本。
