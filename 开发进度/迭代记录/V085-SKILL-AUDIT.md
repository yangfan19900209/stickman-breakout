# V0.8.5 新技能复查与第一关体验保护

## 本轮取舍

用户已认可 V0.8.4 第一关的体验。本轮先创建 [L1-V084-20261110](../../doc/BASELINES.md) 可恢复锚点，再检查新安装技能是否能解决具体遗漏。默认仍使用项目 `cocos-2d-action-games`，保留 Cocos 3.8.8、两关既有美术资源和第一关玩法。

| 读取的专项 skill | 适用结论 | 本轮落地或保留依据 |
| --- | --- | --- |
| `game-ui-ux` | 有可修复的状态反馈与重复绘制 | 修正两关攻击冷却来源；Boss 血条按血量/对象/布局变化重绘，攻击预警仍独立更新 |
| `performance-optimization` | 采用先测量再修改 | 优化前用正常水下路线采集实际 Cocos 绘制分支执行次数；用同一浏览器、视口和操作策略复测。不推导手机 FPS |
| `game-feel` | 补足已有反馈链 | 刀攻击的恢复提示读取近战状态；保留已经调好的停顿、震动、命中图和角色动作 |
| `audio-design` | 先修正声音事件与生命周期 | 水下致命受击不再因状态已变成 dying 而漏音；重开和换关清除事件游标，延迟完成的资源在销毁后释放。未引入音乐总线或修改已接受音量 |
| `input-systems` | 已有方案覆盖主要建议 | 已有命名动作、多指归属、短按缓存、死区、离地容错、提前跳跃缓存；沿用现有操作参数，回归多指、取消和旋转 |
| `camera-systems` | 已有方案覆盖本轮需求 | 已有时间相关平滑、边界、前视、Boss 取景与只读显示插值；本轮不改镜头参数 |
| `level-design` | 用于保护认可节奏 | 保留主路、两次战前补给、分段压力与已有两 Boss 间长度；用真实输入通关检查。白盒方法适合新关卡原型，不用于把当前地图退回几何块 |

本轮未把新装技能全部套进项目：Godot、Unity、Unreal、Phaser 等专用代码不适用当前引擎；程序生成、3D 摄像机、技能树、网络和存档扩展没有当前需求。没有为了“用上技能”新增系统或重画资源。

## 实际修正

- 第一关原先把刀的冷却读成枪械冷却，造成挥刀后按钮看起来立刻就绪；现读近战恢复。近箱自动切割也按实际动作显示。
- 第二关原先所有攻击都除以固定的 0.65 秒。现在鱼叉、声波、鱼雷、刀分别跟随本次攻击的实际间隔；最后一发自动切回鱼叉、期间切刀或拾取新武器，也不会改写上一击的剩余恢复提示。
- Boss 血条几何缓存包含敌人对象、生命上限/当前生命与显示尺寸。生命变化立即更新，换 Boss 或重新布局使缓存失效；隐藏/暂停时不重建。攻击名、阶段与预警继续按原节奏显示。
- 音效在致命受击帧、换关、重开、暂停、静音和异步资源销毁后使用一致的事件消费规则。播放次数作为只读诊断，不代表已完成扬声器或耳机听感验收。

第一关地图、移动物理、战斗规则、敌人/补给分布、镜头参数、所有美术像素与触控图标均对照锚点检查。新增元数据只供反馈使用，不改变伤害、射速和行动时长。

## 本轮完成结果

- 类型检查、268/268 项逻辑检查通过。623 个既有运行文件与 V084 锚点散列一致，既有修改仅在 UI、水下反馈元数据、声音桥接及版本/重置入口。
- 第一关正常输入通关：91.84 秒、剩余 2 格生命；第二关：85.55 秒、剩余 3 格生命。是自动操作策略下的游戏计时，不作为玩家游玩时长。
- 两关触控、冷却、暂停、胶囊与横竖屏专项通过，共保存 32 张最终截图。水下整关验证 1596 次攻击冷却显示；覆盖鱼叉、声波、鱼雷。
- 水下改前路线血条重建 2727 次，改后 81 次。更直接的同一运行统计为：1393 次可见更新中只重建 81 次，避免 1312 次重复工作。两次路线过程不完全相同，不用两次总数之比声称整体性能提升。
- Web 实际运行通过；微信本地包 14,833,741 字节，主包 4,188,943 字节。保留 2 条 Chrome 对人工 touchCancel 的引擎诊断；输入取消断言通过，应用错误和失败请求为 0。
- 项目技能官方格式校验通过，11 个文件与全局副本匹配。同步前检测到另一处更新，已保留其中鼠标/触摸去重、场景组件 ID 与资源包配置规则，再合并本轮经验；详见 [合并记录](../验证记录/v085-skill-merge.json) 和 [同步记录](../验证记录/v085-skill-verification.json)。
