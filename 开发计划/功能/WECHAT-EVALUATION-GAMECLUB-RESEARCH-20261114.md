# 推荐、评价与游戏圈内容串联调研

日期：2026-11-14（北京时间）。范围：记录账号前置条件，核对公开能力与现有实现；本轮没有修改游戏运行代码、重新构建或实际推荐、评价、发帖。

## 账号前置条件

用户本轮补充：**先完成备案 → 改为联网游戏 → 开通相关权限**。好友榜权限工作按这个顺序挂起，保留 A1114-3 和实际 1026 诊断；见[运营记录](../../运营/隐私配置/好友榜隐私声明-20261114.md)。这是当前账号办理条件，不据此认定所有推荐、评价、游戏圈功能都必须申请好友关系权限，也不扩写为所有小游戏的统一规则。

## 结论

现有“推荐游戏”能请求微信官方推荐组件。目前核对的公开资料没有给出“在这个组件内附加星级评价，再自动发布一条文字推荐帖”的完整调用方案。可以设计多个自愿入口，但原生推荐页面是否自带写评价或同步动态，需要当前微信真机页面确认。

| 用户希望的动作 | 核对结果 | 实施边界 |
| --- | --- | --- |
| 游戏内打开推荐页 | 已接入 PageManager 和官方推荐 openlink | 原生页面内容由微信提供；本轮未真机观察其最新布局 |
| 推荐页同时拉起星级／文字评价 | 未找到已核验的评分编辑页 API、openlink 或切换参数 | 既有官方指南记录指向评分主页；可从微信搜索评分入口或小游戏更多面板进入，具体入口以当前微信为准 |
| 推荐后由微信生成推荐动态 | 尚未确认当前平台的具体发布行为 | 需看原生页面选项并验证游戏圈结果；不能凭 isRecommended=true 认定产生了一条帖子 |
| 代码自动发布玩家的文字推荐帖 | 未在所查公开接口、SDK 和示例中发现对应发布接口 | 不能把打开游戏圈、读取发帖数当作发布能力；本轮没有实现或代玩家发帖 |
| 打开游戏圈首页／指定话题 | 官方接口支持 | 原生游戏圈按钮可使用后台生成的真实 openlink；当前代码打开本游戏圈首页 |
| 游戏内生成战报文案，再由玩家去游戏圈发布 | 可作为后续产品方案 | 生成草稿可控；进入圈子后由玩家编辑确认。尚未核验把草稿自动填入微信发帖器的接口，不承诺跨页自动填文 |

“未找到公开方式”仅限本轮证据范围，不等于平台永远不支持，也不排除官方渠道以后提供专用开放页面。

## 关键依据

1. 当前 `RecommendationBridge.ts` 只传入推荐组件 openlink，监听 ready/show/destroy/error。`destroy.isRecommended` 是关闭时观察到的推荐状态；现有 1.0.7 复活奖励沿用该状态，本轮不改变奖励规则。它不能作为打星、评价正文提交或游戏圈帖子发布的回执。
2. 官方 `PageManager.load/show` 的 `query`、`extraData` 明确要求按对应能力渠道说明使用。存在通用参数并不能证明推荐组件支持 `rating`、`comment`、`autoPublish` 等字段，不猜造参数或评分 deep link。
3. 官方 `createGameClubButton` 说明支持进入游戏圈，2.30.3 起可通过 openlink 进入单帖、话题或活动；`CreateGameClubButtonOption` 指向 MP 后台生成的“游戏内跳转 ID”。官方示例也是创建导航按钮，没有自动发布文字内容。
4. 官方 `getGameClubData` 分别提供当天发帖数（type 6）、当天话题发帖数（type 10）、最近推荐时间（type 11）。这是读取数据的接口，返回加密数据／cloudID 等信息，不能据此推断推荐会产生特定帖子或可由代码发布。通用统计也不能证明本次提交的星级、正文或新增帖子。
5. 评分主页与推荐组件的区别沿用[11-13 已记录的官方正文依据](WECHAT-EVALUATION-PLAN.md)。本轮重新核对官方 GitHub 类型定义、SDK 和示例；没有重新读取受访问限制的微信文档站或账号后台，也没有打开真实推荐页。

## 适合本项目的后续方案

先保留当前“推荐游戏”入口。需要鼓励文字反馈时，可另提供“如何写评价”的明确指引；需要游戏圈内容时，可设计“去游戏圈晒战绩”，展示真实的本人关卡成绩及可编辑文案，打开官方游戏圈或后台提供的话题入口，让玩家自主发布。三种结果分别记录，不承诺一次点击自动完成整条流程。

在新增按钮或跳转前，先取得当前真机“推荐游戏”页：核对是否已有星级、写评价、同步游戏圈或内容编辑选项；再由测试玩家自主操作，观察最终评分页和游戏圈内容。若平台原生流程已经包含这些步骤，优先使用它，避免重复引导。没有拿到官方评分／发帖开放页面说明前，不实现猜测跳转。
